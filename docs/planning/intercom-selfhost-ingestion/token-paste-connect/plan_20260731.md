## 2. Phases

### Phase 1 — RED: the route contract

- **Files:** `services/backend-api/tests/test_intercom_integration.py` (new)
- **Steps:** write the full B1-B10 suite against routes that do not exist yet. Model it on
  `tests/test_zendesk_integration.py`. Mock the Intercom client at the module boundary the
  route imports, exactly as the Zendesk tests mock `ZendeskClient`.
  - B1 connect happy path — asserts `workspace_id` from `app.id_code`
  - B2 invalid token → 422 · B3 transient → 502 · B5 no encryption key → 422
  - B4 ciphertext at rest, secrets absent from the response
  - B6 reconnect upserts · B7 auto-provisioned source has `new_conversations: True`
  - B8 `member` → 403 on connect/status/disconnect
  - B9 cross-path conflict, both directions · B10 disconnect leaves the source
- **Validation:** all fail on import/404. **RED for the right reason** — a missing route,
  not a broken assertion.
- **Commit:** `test(intercom): specify the token-paste connect contract (RED)`

### Phase 2 — GREEN: model + migration

- **Files:** `src/models/intercom_integration.py`, `src/models/__init__.py`,
  `alembic/versions/<rev>_intercom_integrations.py`
- **Steps:**
  1. Model per spec, mirroring `ZendeskIntegration` including
     `UniqueConstraint('organization_id')` and the org index.
  2. Export from `src/models/__init__.py` (both the import and `__all__`).
  3. `./venv/bin/alembic revision -m "intercom_integrations"`; set `down_revision` to the
     live-verified head; hand-write `create_table` + the unique constraint + index.
     `downgrade()` drops the table.
  4. `./venv/bin/alembic heads` → **exactly one head** (B11).
- **Validation:** `alembic upgrade head` against a scratch DB, then `alembic heads`.
- **Commit:** `feat(intercom): IntercomIntegration model + migration`

### Phase 3 — GREEN: the client and the routes

- **Files:** `src/api/routes/intercom_integration.py`, `src/api/main.py`
- **Steps:**
  1. `IntercomClient` (module-local, mirroring `ZendeskClient`'s error taxonomy):
     `validate()` → `GET https://api.intercom.io/me` with `Authorization: Bearer <token>`,
     raising `IntercomAuthError` on 401/403 and `IntercomTransientError` on 5xx/timeouts.
     Return `{"workspace_id": app.id_code, "workspace_name": app.name, "admin_id": id}` —
     read the shape from the existing OAuth callback (`integrations.py:1066-1072`), do not
     invent it. **Fixed host `api.intercom.io`** → no SSRF DNS gate needed (Asana's
     reasoning; unlike Zendesk there is no per-org subdomain).
  2. `router = APIRouter(prefix="/api/v1/integrations/intercom", tags=["intercom"])`.
     **Note the prefix collides with the OAuth routes in `integrations.py`
     (`/intercom/oauth/...`) only by path segment, not by full path** — verify at startup
     that both mount cleanly and no route is shadowed.
  3. `POST /connect`, `GET /status`, `DELETE /disconnect`, each with
     `dependencies=[Depends(require_admin_or_owner)]`.
  4. `_ensure_default_feedback_source` seeding `triggers={"new_conversations": True}`,
     `auto_import=True`, `integration_id=None`, `provider_config={"workspace_id": ...}`.
     **Copy Zendesk's inline comment explaining why the trigger must be seeded** — the
     reason is non-obvious and its absence is a silent-ingestion bug.
  5. D6 guard: reject if an active OAuth `Integration(type="intercom")` exists for the org;
     and make the OAuth path reject if an active `IntercomIntegration` exists.
  6. Register the router in `main.py` next to Zendesk's.
- **Validation:** `pytest tests/test_intercom_integration.py -v` green; then the
  webhook-adjacent regression set from the previous aspect.
- **Commit:** `feat(intercom): token-paste connect, status and disconnect routes`

## 4. Edge Cases

| Case | Expected |
|---|---|
| Reconnect with a new token | Upsert; `workspace_id` refreshed; existing `client_secret` preserved when omitted |
| `client_secret` omitted | Accepted, stored `NULL`; pull works, webhook verification stays on the global env var until `webhook-per-org-secret` |
| Token valid but workspace id missing from `/me` | 422 — a connection with no discriminator can never match a source, so failing loudly beats storing a dead row |
| Org already OAuth-connected | 409 with a message naming the other path (D6) |
| Disconnect then reconnect | New row or reactivated row; the FeedbackSource is untouched and reused |
| `member` role | 403 before any Intercom call is made |

## 5. Agent Execution Notes

**Checkpoints:** after Phase 2 (confirm exactly one alembic head, live), and after Phase 3
(confirm all three routes enforce RBAC).

**Ask before proceeding if:**
- `alembic heads` shows more than one head at any point — stop, do not "fix" it by editing
  `down_revision` on an existing revision.
- The `/me` response shape differs from what the OAuth callback parses.
- The router prefix shadows an existing `integrations.py` route.

**Do not** touch `_find_matching_sources` in this aspect — the discriminator widening is
`tenancy-discriminator`'s job and needs its own characterization tests over the P0
guarantees. Storing `workspace_id` is all that happens here.
