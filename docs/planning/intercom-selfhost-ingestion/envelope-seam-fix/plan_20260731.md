### Phase 0 — Confirm no other producer depends on the stripped shape

  1. `grep -rn 'source_type="intercom"\|"intercom"' services/backend-api/src services/worker-service/src`

- **Commit:** none (investigation).

### Phase 1 — RED: the golden fixture and two failing tests

- **Goal:** encode the seam as an executable contract that fails against today's code.
- **Prerequisites:** Phase 0.
- **Files to create:**
  - `services/worker-service/tests/fixtures/intercom_webhook_envelope.json`
  - `services/worker-service/tests/test_intercom_envelope_seam.py`
- **Files to modify:**
  - `services/backend-api/tests/test_intercom.py`
- **Steps:**
  1. **Write the fixture.** A complete `conversation.user.created` envelope:
     top-level `type`, `topic`, `app_id`, and `data.item` carrying `id`,
     `conversation_message.body` (HTML, to exercise `strip_html`), and
     `conversation_message.author` with `id`/`name`/`email`. Derive the shape from the
     envelopes already encoded in the passing
     `services/worker-service/tests/test_intercom_adapter.py:91-108`, and put a header
     comment in the JSON's sibling test naming that provenance — the fixture is the
     contract, so where it came from must be traceable.
  2. **Worker seam test** (`test_intercom_envelope_seam.py`), loading the fixture from
     disk (**never inline** — the point is that both suites read one file):
     - `test_adapter_extracts_text_from_golden_envelope` — `extract_content(fixture, {})`
       returns non-empty `text` equal to the stripped body. **Passes today** (the adapter
       is already correct); it pins the adapter side against future drift.
     - `test_adapter_yields_nonempty_dedup_id` — `get_external_ids(fixture)` returns a
       non-empty conversation id (A4).
     - `test_process_event_creates_feedback_item` — drive
       `_process_event_for_source` with a source whose `triggers={"new_conversations": True}`
       and `auto_import=True`, passing **the exact `event_data` the route queues today**
       (i.e. `fixture["data"]`). Assert a `FeedbackItem` is created.
       **← This is the RED test.** Today it returns `{"status": "empty_text"}`.
     - `test_keyword_trigger_matches_on_body` (A5).
     - `test_redelivery_is_deduplicated` (A4).
  3. **Backend contract test** (in `test_intercom.py`): load the same fixture via a path
     relative to the test file, POST it to `/api/v1/webhooks/intercom/events` with
     `queue_source_event` patched, and assert the captured `event_data` **is the whole
     fixture**. Fixture-missing must **fail**, never skip.
  4. **Rewrite** the existing assertion at `test_intercom.py:438`
     (`event_data=payload["data"]`) to assert the envelope. Rewrite in place with a
     comment recording that it previously pinned the defect — the same treatment
     `test_intercom.py:408-415` already applies to the tenancy fix, so follow that
     precedent verbatim.
- **Validation (must be RED, for the right reason):**
  ```bash
  cd services/worker-service && ./venv/bin/pytest tests/test_intercom_envelope_seam.py -v
  cd services/backend-api  && ./venv/bin/pytest tests/test_intercom.py -v
  ```
  Expect `test_process_event_creates_feedback_item` to fail with **`empty_text`**, and the
  backend contract test to fail on the stripped shape. **A failure for any other reason
  means the test is wrong — fix the test, not the production code.**
- **Commit:** `test(intercom): pin the webhook→adapter envelope contract (RED)`

## 4. Testing Strategy

**Unit** — adapter extraction, dedup id, keyword triggers (worker).
**Integration** — `_process_event_for_source` end-to-end into a `FeedbackItem` (worker);
route → queue payload capture (backend).
**Contract** — the shared fixture, asserted from both sides. This is the artifact whose
absence caused the defect; it is the deliverable, not a nice-to-have.

**Manual verification** (optional, after Phase 2):
```bash
redis-server &                       # shared, one per machine
cd services/backend-api && ./start.sh
cd services/worker-service && ./start.sh
# POST the golden fixture to /api/v1/webhooks/intercom/events with a valid
# X-Hub-Signature computed from INTERCOM_CLIENT_SECRET, then confirm a feedback
# item appears at http://localhost:3000/feedbacks
```
Note the manual path still needs `INTERCOM_CLIENT_SECRET` set — the verifier fails closed.
That is expected and is what `webhook-per-org-secret` later addresses.

| `customer_email` | Still `NULL`; only `author_email` in `source_metadata`. **Correct for this aspect** — R7 is a later one. Do not "improve" it here. |
