## Summary of decisions (read this first)

| Decision | Choice | Rationale |
|---|---|---|
| Where the pure functions live | **New sibling module `services/worker-service/src/adapters/intercom_parts.py`** (spec's "sibling module" option) | `adapters/intercom.py` is the **webhook-envelope** adapter (`IntercomAdapter` + `check_triggers`/`extract_content`); spec AC5 demands its extraction paths and tests stay untouched. Pull-conversation extraction, the merge format, and the diff are not webhook concerns — a sibling module keeps single-responsibility and gives `pull-enrichment` a clean import surface (`src.adapters.intercom_parts`). No change to `adapters/__init__.py` (it exports adapter classes only; consumers import the module directly). |
| Reuse of `_contact_email` / `strip_html` | Imported **from `.intercom`** into the sibling module (`from .intercom import _contact_email, strip_html`) | They are the shared parsing primitives; AC2 requires testing the rule "through the new path". The cross-module import of an underscore-prefixed name is intentional and intra-package — documented in both module docstrings. `intercom.py` itself is **not modified**. |
| `extract_reply_parts` signature | `extract_reply_parts(conversation: Dict[str, Any]) -> List[Dict[str, Any]]` → `[{part_id, author, body, created_at}]` | Pure function, conversation object in, plain dicts out (spec:19-21). Author **object** retained (not flattened) so `pull-enrichment`/UI can make attribution decisions (spec:21). |
| Reply-family filter | `type == "conversation_part"` **and** `part_type == "comment"` | The client aspect's verified shape (per its spec: "reply parts are `part_type: "comment"` with `type: "conversation_part"`"). Notes, assignments, open/close, tags, rating parts are system events → excluded. The first message is the top-level `conversation_message` object and is **not in `conversation_parts`** (user-pinned contract, spec:32); no id-based first-message filter is implemented (see ambiguities). |
| Parts accessor tolerance | Tiny `_parts_of(conversation)` helper accepting the wrapped object `{"conversation_parts": [...]}` (the parse already proven at `intercom.py:221`) **and** a bare list; anything else → `[]` | The single biggest open risk (spec OQ, client aspect R1a/R1b) is the exact wrapper shape of the verified response. 4 lines of tolerance removes an entire class of API drift; field names (`body`, `part_type`) are **not** hedged — those follow the client contract exactly. |
| `extract_rating` signature | `extract_rating(conversation: Dict[str, Any]) -> Optional[Dict[str, Any]]` → `{"rating": int, "remark": str, "rated_at": str}` with **`remark`/`rated_at` keys omitted when absent**; `None` when no rating | Spec:22-23 (`{rating, remark?, rated_at?}`, "None when absent"). `rated_at` sourced from `conversation_rating["created_at"]` per Intercom's documented rating shape; OQ3 resolved — absent → omit the key, never a `None` value. Reads `conversation["conversation_rating"]` (the client aspect's pinned "conversation objects carry `conversation_rating`"). |
| Merge format | `format_reply_merge(reply: Dict[str, Any]) -> str` returning exactly `"\n\n--- Reply by {author_name} ({created_at}) ---\n{body}"`; `author_name = (author.get("name") or "unknown")`; `created_at` passed through via `str()` | Pinned verbatim by tests (AC4; PRD:141). Input is one extracted part dict so callers cannot assemble the string wrong. `unknown` fallback avoids a double-space attribution line on nameless authors (flagged as a decision). |
| Idempotent diff | `new_reply_parts(parts: List[Dict[str, Any]], merged_part_ids) -> List[Dict[str, Any]]` — pure; returns `parts` whose `part_id` is not in `merged_part_ids`; preserves order | Idempotency key = `part_id` membership (spec:29, AC4). Pure so it is unit-testable here; `pull-enrichment` computes the merged set from `source_metadata["replies"]` and calls it — re-merge becomes a no-op by construction. |
| Stored metadata shape (pinned here for both aspects) | `source_metadata["replies"]` = `extract_reply_parts` output verbatim (array of `{part_id, author, body, created_at}`, membership read from `part_id`); rating = `source_metadata["rating"]` / `["remark"]` / `["rated_at"]` (keys omitted when absent) | PRD R3/R6; N1/N2 (UI) read this shape later. `source_metadata` is free-form JSON on `FeedbackItem` — no migration (PRD:133). `pull-enrichment` writes it; this aspect pins it with tests so the two aspects agree. |
| Admin/bot authors | Content **included** in the parts list; `_contact_email(author)` → `None` (existing rule, `intercom.py:21-33`, unchanged); never becomes `customer_email` | AC2, PRD R2. Tested through the new path: `_contact_email(extract_reply_parts(conv)[i]["author"])` on user/contact/lead/admin/bot fixtures. The merge itself never sets `customer_email` (the item already has it from the first message). |
| Rating in text | **Never** appended to text (R6) — no `format_rating_merge` function exists | A "Rating: 5/5" line would skew sentiment; PRD R6, webhook-parity "Rating: X/5" form is explicitly NOT used. |
| Test file | New `services/worker-service/tests/test_intercom_parts.py` | Keeps `test_intercom_adapter.py` byte-for-byte untouched (AC5) — same pattern as the write-client precedent (`test_intercom_client_writeback.py`). |
| Field names in fixtures | `part_id = part["id"]`, `body`, `author`, `created_at` (Unix int) — mirror the client aspect's verified shape exactly (spec OQ) | Spec:55-56: fixtures mirror the client aspect's pinned shape; field-name variants are flagged, not supported. |

### Phase 2: GREEN — `intercom_parts.py`

- **Goal:** Implement the pure module; new tests green; existing adapter tests unchanged and green.
- **Prerequisites:** Phase 1 committed (RED).
- **Files to create/modify:**
  - Create `services/worker-service/src/adapters/intercom_parts.py`
- **Implementation steps:**
  1. Create the module with this shape (docstrings mandatory — the module is the pull-enrichment contract):
     ```python
     """Reply/rating extraction from Intercom *conversation* objects (pull path).

     The webhook adapter (adapters/intercom.py) parses event-shaped payloads;
     this module parses the conversation object the pull client returns
     (conversation_parts + conversation_rating). It reuses strip_html and
     _contact_email from adapters/intercom.py — importing the underscore names
     is deliberate: they are the shared parsing primitives, and intercom.py is
     deliberately untouched so webhook behavior never moves.

     The merge format is pinned by tests in test_intercom_parts.py:
       "\\n\\n--- Reply by {author_name} ({created_at}) ---\\n{body}"
     Idempotency is by part_id membership (see new_reply_parts).
     """
     from typing import Any, Dict, List, Optional

     from .intercom import _contact_email, strip_html

     REPLY_PART_TYPES = {"comment"}
     ```
  2. `_parts_of(conversation) -> List[Dict[str, Any]]` — accept `conversation["conversation_parts"]` as either the wrapped object (`{"conversation_parts": [...]}`, the parse at `intercom.py:221`) or a bare list; anything else / missing → `[]`.
  3. `extract_reply_parts(conversation) -> List[Dict[str, Any]]`:
     - For each part from `_parts_of`: keep iff `part.get("type") == "conversation_part"` and `part.get("part_type") in REPLY_PART_TYPES`.
     - `part_id = part.get("id")` — **skip the part if falsy** (no id ⇒ no idempotency key ⇒ cannot be merged; keep the module pure, no logging — the caller logs).
     - `body = strip_html(part.get("body") or "")`.
     - `author = part.get("author") or {}`.
     - `created_at = str(part.get("created_at")) if part.get("created_at") is not None else ""` (pass-through; Intercom sends Unix seconds).
     - Emit `{"part_id": part_id, "author": author, "body": body, "created_at": created_at}` in original order.
  4. `extract_rating(conversation) -> Optional[Dict[str, Any]]`:
     - `rating_obj = conversation.get("conversation_rating")`; if not a dict or `rating_obj.get("rating") is None` → return `None`.
     - Build `{"rating": rating_obj["rating"]}`; add `"remark"` only when `rating_obj.get("remark")` is truthy (non-empty); add `"rated_at"` only when `rating_obj.get("created_at") is not None` (→ `str(...)`).
  5. `format_reply_merge(reply: Dict[str, Any]) -> str`:
     ```python
     author_name = (reply.get("author") or {}).get("name") or "unknown"
     return (
         f"\n\n--- Reply by {author_name} ({reply.get('created_at', '')}) ---\n"
         f"{reply.get('body', '')}"
     )
     ```
  6. `new_reply_parts(parts, merged_part_ids) -> List[Dict[str, Any]]`:
     - `merged = set(merged_part_ids or [])`; return `[p for p in parts if p["part_id"] not in merged]` (order preserved).
  7. Run the suite; fix only `intercom_parts.py` until green — do not weaken a test to pass.
- **Validation:**
  - `cd services/worker-service && pytest tests/test_intercom_parts.py -v` — all green.
  - `cd services/worker-service && pytest tests/test_intercom_adapter.py -v` — green, **unchanged** (AC5 guard).
  - `git diff --stat services/worker-service/src/adapters/intercom.py` — empty (untouched).
- **Commit message:** `feat(worker): intercom reply/rating extraction + idempotent merge from conversation parts (TDD)`

## 6. Edge Cases & Error Handling

| Case | Handling (pinned) |
|---|---|
| `conversation_parts` wrapper drift (wrapped object vs bare array) | `_parts_of` accepts both; anything else → `[]`. Field-name variants (`body` vs `text`) are **not** supported — flagged, not hedged (spec OQ). |
| First message present in `conversation_parts` after all | Contract says it lives at top level as `conversation_message`, never in parts. If client-aspect verification contradicts this, comment parts would duplicate first-message text in the merge; mitigation (skip part whose content matches `conversation_message`) is deliberately **not** pre-implemented — see §8 ambiguity 1. |
| Non-comment parts (note, assignment, open/close, tags, rating part) | Excluded by the `part_type == "comment"` filter. The rating part (if one exists as a part) is excluded too — rating comes from `conversation_rating`. |
| Part without `id` | Skipped in `extract_reply_parts` — no idempotency key. No log from the pure function (caller logs if it cares). |
| Part without `body` / without `author` | `""` / `{}` — merge renders `"\n---\n"` and `"unknown"` respectively; never crashes. |
| Author without `name` | `format_reply_merge` falls back to `"unknown"` (avoids a double-space attribution line). |
| `created_at` missing | Rendered as `""` → `"()"` in the attribution line. Cosmetic, malformed-payload only; Intercom always sends it. Tested shape: Unix int passed through `str()`. |
| Rating absent / rating value missing | `None` — the caller stores nothing (pull-enrichment omits the rating keys). |
| `remark` empty string or absent | Key omitted from the rating dict (never `None`/`""` stored) — keeps `source_metadata` clean and matches OQ3. |
| Admin/bot authors | Content included in parts list; `_contact_email` → `None`; merge never sets `customer_email` (PRD R2/R3). |
| Duplicate `part_id` within one conversation | `new_reply_parts` membership set dedups naturally; the stored list may hold duplicates only if the API emits them (it does not). |
| Rating in text | Never — no rating formatter exists by design (PRD R6). |
| Idempotency across runs | `new_reply_parts` + `source_metadata["replies"]` part_id membership → re-merge is a no-op by construction (test 20). |

## 8. Spec ambiguities flagged

1. **First message presence in `conversation_parts`** — spec/user contract states the first message is the top-level `conversation_message` object, NOT in `conversation_parts` (spec:32). If the client aspect's verification shows the parts array *does* contain the opening comment part, this filter would merge duplicate first-message text. Flagged, not pre-implemented: the fix (skip the part whose body matches `conversation_message.body` or whose `id` equals `source.id`) is a one-line filter in `extract_reply_parts` if needed.
2. **`conversation_parts` wrapper shape** — wrapped object (detail GET, `intercom.py:221`) vs bare array (possible search `display_as` shape). `_parts_of` tolerates both; fixtures use the wrapped form as the primary and test the bare form explicitly.
3. **`rated_at` source key** — pinned to `conversation_rating["created_at"]` (Intercom's documented rating object). If the client aspect's verified shape names it differently, change the single line in `extract_rating` and the fixture — no other code depends on it.
4. **`created_at` type/format in the attribution line** — pinned as pass-through `str()` (Unix seconds in practice). If the client returns ISO strings, rendering is unchanged; the exact-string test (15) pins whatever the fixture says, so both sides stay in agreement.
5. **`author_name` fallback** — spec pins the format with `{author_name}` but not the no-name behavior; plan pins `"unknown"`. If product prefers an empty string, it is a one-word change in `format_reply_merge` plus two tests.
