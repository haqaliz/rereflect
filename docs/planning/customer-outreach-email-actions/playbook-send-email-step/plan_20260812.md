## 6. Edge Cases & Error Handling

- Missing `cs_owner_user_id` (customer has no CS owner) ⇒ loud per-step failure
  (`ok=False`, error mentions owner) — never silent, per PRD risk line
  (`prd.md:218-220`).
- `cs_owner_user_id` set but `users` row gone ⇒ loud per-step failure.
- Unknown template key in config ⇒ loud per-step failure with the key in the error.
- Missing/unknown `recipient` or missing `template` ⇒ loud per-step failure; sender never
  called.
- Opted-out ⇒ sender returns `skipped: opted out` ⇒ entry `ok=False` with
  `result.status="skipped"` — loud in action_log, never a false success (PRD goal #4).
- In cooldown ⇒ `skipped: in cooldown` (the outreach cooldown, Redis DB 1 — the engine's
  60-min playbook rate limit at `playbook_engine.py:54-60` is orthogonal and untouched).
- No `RESEND_API_KEY` ⇒ `failed: email not configured` (sender, loud).
- `health.customer_name` null ⇒ email local-part fallback; org row missing or
  `product_name_display` null ⇒ "Rereflect" (backend fallback `issue_drafter.py:57`).
- Sender contract says never-raise (`outreach-core/plan_20260812.md:208`); if it ever does,
  `_run_actions`'s catch-all records `{ok: False, result: None, error: str(exc)}`
  (`playbook_engine.py:143-148`) — already handled, no change.
- Run status: only `sent` contributes `ok=True`; skip/fail leaves the run to other steps
  (derivation `playbook_engine.py:90-94` unchanged).
