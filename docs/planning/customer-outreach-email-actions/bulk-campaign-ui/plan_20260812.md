## 6. Edge Cases & Error Handling

- **No LLM configured** → draft button hidden entirely (create-issue/page.tsx:241-256
  probe); if it still renders (probe raced) and draft returns 409, show the
  backend detail via toast (issueDraft.ts:41-45 pattern).
- **Over cap** (>500) → client-side destructive guard (BulkRunPlaybookDialog.tsx:182-190)
  AND server 422 surfaced inline (destructive Alert with `detail`).
- **422 validation** (subject >200, body >20,000) → `maxLength` attributes + live
  counters prevent it client-side; a server 422 still renders inline, never a
  silent failure.
- **Empty cohort** (`cohort === null`, dialog can't open) + `matched === 0` →
  confirm step disabled ("No recipients to email").
- **Draft over edited fields** → `window.confirm('Replace your text with the AI
  draft?')`, cancelled draft leaves fields untouched (create-issue/page.tsx:472-486).
- **Preview skip breakdown** — `skipped` includes opted-out / no-email / archived
  (prd.md:94-95); label honestly: "N will be emailed, M skipped (opted out or no
  email)".
- **Retry with nothing queued** — button hidden when `counts.queued === 0`; if
  the endpoint still 422s, toast its detail.
- **Unsubscribe without/invalid token** → failure state, no API call when the
  token is missing; 400 → failure state (outreach-core/spec.md:46).
- **Unsubscribe HTML response** — the backend may answer HTML; the client keys
  off HTTP status, not body shape (§Open questions).
- **Stale preview** — cancelled flag on the preview effect (BulkRunPlaybookDialog.tsx:78-92)
  so a rapid cohort switch can't show a stale count.
- **Members (role < admin)** — item hidden via `isAdminOrOwner`; a 403 that
  sneaks through is toasted with its detail.
