## 6. Edge Cases & Error Handling

- **Blank/non-email `customer_email`:** normalized `strip().lower()`; empty or no `"@"`
  → skip counted + row `skipped: invalid email` (never silently dropped).
- **Opted-out mid-campaign:** queue-time count is informational; the sender re-checks at
  send time and the task flips the row to `skipped: opted out` (spec R2 step 4).
- **Dead worker mid-campaign:** recipients stay `queued`, campaign stays `in_progress`
  → operator hits retry; only `queued` rows re-enqueue, terminal rows are immutable.
- **Double-submit of the same campaign:** each POST creates a new campaign (no
  idempotency key); the shared Redis cooldown in the sender is the cross-campaign dedupe.
- **Retry racing a live task:** terminal-guard in the task makes the duplicate dispatch
  a no-op.
- **Dispatch failure:** per-recipient, caught + logged + surfaced in `errors` (response
  still 202); retry recovers.
- **Org-scoping:** cohort resolution org-scoped (`cohort_service.py:39-46`); campaign
  rows use `current_org.id`; list/retry 404 on cross-org campaign ids.
- **Cap semantics:** count_only previews the true count above 500; the real run 422s.
- **All-skipped cohort:** campaign `done` immediately, `queued == 0` (no orphan
  `in_progress` campaign waiting on tasks that will never run).
- **No-key at send time:** sender returns `failed: email not configured` → recipient
  row `failed`, campaign still completes `done` — loud, never a false success (PRD
  `prd.md:49-50`).
