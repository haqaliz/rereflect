## Phase 1 — `events/emit`: no default secret, constant-time compare (F1)

**Goal:** close the most exposed hole. Independent of every other phase; land it first.

**Why it is safe:** `/api/internal/events/emit` has **no production caller** — verified by grep
across `worker-service/src` and `analysis-engine/src`. `emit_event` itself is used heavily but
always as a direct in-process call inside backend-api. Zero migration risk.

**Files:** `services/backend-api/src/api/routes/events_ws.py`,
`services/backend-api/tests/test_event_emitter.py`

**RED**
1. In `test_event_emitter.py`, add `TestInternalEmitAuth`:
   - `test_unset_secret_rejects_even_with_matching_header` — patch
     `events_ws.INTERNAL_SECRET` to `""`, POST with `X-Internal-Secret: ""` **and** with
     `"dev-secret"`; expect `403` both times.
   - `test_wrong_secret_rejected` — patch to `"real-secret"`, send `"wrong"` → `403`.
   - `test_correct_secret_accepted` — patch to `"real-secret"`, send `"real-secret"` → `200`.
   - `test_missing_header_rejected` — no header, secret set → `403`.
2. Run: the first test **must fail** (currently `"dev-secret"` is accepted when unset).

**GREEN**
3. `events_ws.py:52` → `INTERNAL_SECRET = os.getenv("INTERNAL_EVENTS_SECRET", "")`.
4. `events_ws.py:157` → reject when the secret is unset, and compare in constant time:
   ```python
   if not INTERNAL_SECRET or not x_internal_secret or not hmac.compare_digest(
       x_internal_secret, INTERNAL_SECRET
   ):
       raise HTTPException(status_code=403, detail="Invalid internal secret")
   ```
   Add `import hmac` if absent. Keep the existing `403` (not `401`) — matches the current contract
   and the repo's `HTTPBearer` convention.
5. **`compare_digest` raises `TypeError` on non-ASCII** — wrap or pre-encode. Add a test sending a
   non-ASCII header expecting `403`, not `500`.
6. Update the pre-existing `test_event_emitter.py:148,166` — both read
   `os.getenv("INTERNAL_EVENTS_SECRET", "dev-secret")` and will now resolve to `""`. Patch
   `events_ws.INTERNAL_SECRET` explicitly instead of reading the env.

**Validation:** `pytest tests/test_event_emitter.py -v` green; full backend suite ≥ baseline.

**Commit:** `fix(events): reject internal emit when the shared secret is unset`

## Phase 2 — Tenancy guards on all four branches (F5, F7, F8)

**Goal:** the core fix. No payload can cause a write attributed to an org it doesn't belong to.

**Prerequisite:** none. **This must land before any Intercom envelope/adapter work, ever.**

**Files:** `services/worker-service/src/tasks/source_events.py`,
**new** `services/worker-service/tests/test_source_events.py`

**RED**
1. Create `tests/test_source_events.py`. Model the fixtures on
   `tests/test_zendesk_adapter.py` (`_make_org`, `_make_*_integration`, `_make_*_source`) — the
   worker suite has no shared org factory, so define local helpers as that file does.
2. For **each** of `slack`, `intercom`, `email`, `webhook`, write:
   - `test_missing_<disc>_returns_empty_not_cross_tenant_fanout` — seed **two** orgs each with an
     active source of that type, call `_find_matching_sources(db, "<type>", {})`, assert `== []`.
   - An empty-string variant (`{"workspace_id": ""}` etc.) — mirrors
     `test_zendesk_adapter.py:479-491`.
   - **A positive case**: with a correct discriminator, assert exactly org A's sources come back
     and org B's are **absent**. This is what proves the guard didn't just break resolution.
3. Add `test_zendesk_branch_unchanged` asserting the existing zendesk behaviour still holds.
4. Run: all eight negative tests **must fail** (they currently return both orgs' sources).

**GREEN**
5. In `_find_matching_sources`, add the guard to each of the four branches, matching the zendesk
   shape at `:180-182` exactly:
   ```python
   if source_type == "slack":
       team_id = provider_context.get("team_id")
       if not team_id:
           return []
       ...
   ```
   Same for `intercom`/`workspace_id`, `email`/`source_id`, `webhook`/`source_id`. Then de-indent
   each branch body one level and keep the existing inner `else: return []`.
6. **Watch the falsy set.** `""` must be caught as well as `None` — the Intercom OAuth callback
   stores `workspace_id` with a `""` default (`integrations.py:1051`). `not x` covers both. Do not
   use `is None`.
7. Consider a short comment on each guard citing the cross-tenant reason, mirroring the docstring
   style of `test_zendesk_adapter.py:462`.

**Validation:** `pytest tests/test_source_events.py -v` green; worker suite ≥ 1417.

**Commit:** `fix(worker): scope every source branch to its tenant, not just zendesk`

## Phase 3 — Intercom signature fails closed (F2, F6 part)

**Goal:** unsigned Intercom payloads are rejected, including on a default install.

**Prerequisite:** Phase 2. Both must be present before merge — either alone leaves the chain
exploitable from the other end.

**Files:** `services/backend-api/src/api/routes/source_webhooks.py`,
`services/backend-api/tests/test_intercom.py`

**RED**
1. Add pure-function tests mirroring `test_zendesk_webhook.py:250-268`:
   `test_empty_secret_returns_false_fail_closed`, `test_none_secret_returns_false_fail_closed`.
2. Add a route test mirroring `test_zendesk_webhook.py:409-430`: with the secret unset, POST a
   payload → expect `401` and `mock_queue.assert_not_called()`.
3. Add `test_webhook_rejects_tampered_body` — sign payload A, send payload B → `401`.
4. Add `test_non_ascii_signature_returns_401_not_500`.
5. **Rewrite** `test_webhook_processes_conversation_created` (`:294-325`). It currently pins
   `provider_context={"conversation_id": "conv_100", "workspace_id": None}` as the expected
   contract. Add `"app_id": "abc123"` to the payload and assert
   `workspace_id: "abc123"` flows through. **Rewrite, do not extend** — the old assertion encodes
   the vulnerability as correct.
6. Audit the other payload fixtures (`:251-260, 335-344, 366-376, 390-393`) — none contain
   `app_id`; add it wherever a positive path is asserted.
7. Run: tests from steps 1–4 **must fail**.

**GREEN**
8. `verify_intercom_signature` (`:268-270`) → `return False` on a falsy secret, matching
   `_verify_zendesk_signature` (`:383-403`). Keep the warning log.
9. Guard `compare_digest` against non-ASCII (same fix shape as Phase 1 step 5).
10. **Do not touch the SHA-1 algorithm.** Intercom's `X-Hub-Signature` is HMAC-SHA1 per vendor
    spec, and HMAC-SHA1 is unaffected by SHA-1 collision attacks. Changing it would break real
    deliveries.

**Validation:** `pytest tests/test_intercom.py -v` green; backend suite ≥ baseline.

**Commit:** `fix(intercom): fail closed when the webhook secret is unset`

## Edge cases

- **`""` vs `None`** — `workspace_id` can be `""` from the OAuth callback's default. Use `not x`.
- **Non-ASCII signature headers** → `compare_digest` `TypeError` → 500. Guard in all three verifiers.
- **In-flight Celery tasks across deploy** — a task queued pre-fix with `workspace_id=None` that
  runs post-fix returns `[]`. That is the desired outcome; no drain required.
- **`_find_matching_sources` has a second caller** — `zendesk_sync.py:176`, passing a trusted
  subdomain from a column. The zendesk branch is untouched, so it is unaffected; assert it.
- **Slack's handler already early-returns** on missing `team_id` (`source_webhooks.py:140-142`), so
  its guard is defence-in-depth. Add it anyway — it is one new call site away from live.
- **Email's org resolution loads every org's sources** (`email_webhooks.py:175-190`) and its rate
  limit is keyed on the **resolved** org, throttling the victim. Out of scope to restructure, but
  do not make it worse; note it for the follow-up.
