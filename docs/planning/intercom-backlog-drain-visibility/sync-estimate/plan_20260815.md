  (intercom_sync.py:311-318). `changed_feedback_ids`/`dropped_by_cap` are the
  pull-enrichment aspect's additive keys. This aspect adds `backlog_remaining`

- **The model column is owned by db-status-api (R3).** The worker mirror

## 1. Placement decisions (pinned)

### 1.1 The formula — one expression, pinned

In `_sync_org`, after the pagination loop ends and before the `return` dict:

```python
remaining_estimate = (
    max(0, total_count - conversations_seen)
    if total_count is not None
    else None
)
```

- `total_count is None` → `None` (unknown total → no estimate this run, PRD R3 risk
  resolution: honest `None`, never a fabricated number).
- `total_count >= 0` int → `max(0, total - seen)`. The `max(0, ...)` is load-bearing:
  the `>=` boundary re-fetch can inflate `seen` above the window total (spec open
  question; pinned by the negative-delta test, Phase 1 #3).
- Result dict key is `"backlog_remaining"` (matches the column/API/frontend naming
  everywhere in this feature).

### 1.2 Where the last-page total is captured

- Initialize **before** the loop, alongside the other counters (:193-200):

  ```python
  total_count: Optional[int] = None
  ```

- The loop's `search_conversations` call site (:203-205) becomes a 3-tuple unpack:

  ```python
  conversations, next_cursor, total_count = client.search_conversations(
      updated_since=updated_since, starting_after=starting_after
  )
  ```

  Each page overwrites the binding, so after the loop `total_count` holds the **last
  page's** value. Because `total_count` is per-query constant this equals any page's
  value; overwriting is deliberate (spec: "the last page's total"), not an accident.
  Do NOT take it from the first page only — the loop-bound capture is the pinned shape.
- The estimate is computed after the loop, so an empty run (`pages` looped with empty
  pages, or `max_updated_at is None`) still yields `0`/`None` correctly — the formula
  never depends on having seen anything.
- If the run hits the 20-page cap, the estimate is still computed from partial `seen`
  — honest for the window (the cursor resumes next run; PRD: "reports progress, it
  does not speed it up").

### 1.3 Result dict — additive key only

`_sync_org`'s return (:311-318) gains one line:

```python
return {
    "conversations_seen": conversations_seen,
    "conversations_ingested": conversations_ingested,
    "changed_feedback_ids": changed_feedback_ids,
    "dropped_by_cap": dropped_by_cap,
    "no_source_match": not sources,
    "cursor": max_updated_at,
    "backlog_remaining": remaining_estimate,
}
```

- `changed_feedback_ids` / `dropped_by_cap` (enrichment) untouched — the additive-key
  test (Phase 1 #5) asserts the FULL key set so a future deletion cannot silently pass.
- `_sync_intercom_org_body` returns `{"status": "ok", **result}` (:400) — the key flows
  into the task result automatically (PRD OQ2: yes, additive key, useful in task logs).
  No change needed there for the return shape.

### 1.4 Persistence alongside `last_sync_status = "ok"`

In `_sync_intercom_org_body` (:366-368):

```python
integ.last_sync_status = "ok"
integ.last_error = None
integ.backlog_remaining = result["backlog_remaining"]
integ.updated_at = datetime.utcnow()
db.commit()
```

- **Always written on a completed run — including `None`.** A completed run with an
  unknown total writes `backlog_remaining = None`, overwriting any prior value (PRD R3
  risk-table decision: "unknown total on a completed run → set backlog_remaining =
  None (honest)"). Never skip the write; skipping would leave a stale number that looks
  fresh next to a fresh `last_sync_status = "ok"`.
- Commit semantics unchanged: still the single `db.commit()` at :369, still inside the
  same transaction as `_sync_org`'s work. No new session, no new commit.
- OAuth/never-synced rows are untouched by design: the pull iterates
  `IntercomIntegration` rows only; OAuth orgs never run `_sync_org`, their column stays
  NULL (no migration default — db-status-api, house convention).

### 1.5 Reset-to-None in `_persist_terminal_status` — one change, both error paths

Add one line inside `_persist_terminal_status` (:95-114), next to the other terminal
writes:

```python
row.last_sync_status = status
row.last_error = error[:2000] if error else None
row.backlog_remaining = None
row.updated_at = datetime.utcnow()
```

- The helper is the ONLY writer of terminal statuses and both error call sites route
  through it: auth_error (:358) and transient (:403). One line covers both — do NOT
  add resets at the call sites (duplication, drift risk).
- This is the stale-number-prevention pin (PRD R2, spec AC2): a failed run leaves
  `backlog_remaining = None`, never a stale count beside a failed status.
- The helper's separate-session design is unchanged (its docstring's rollback rationale
  stands).

### 1.6 `_fake_client` gains a third element per page (padding, not surgery)

`_fake_client` (:175-191) currently builds `side_effect = [(convs, cursor), ...]`.
Change to:

```python
client.search_conversations.side_effect = [
    (
        [IntercomClient._normalize(c) for c in convs],
        cursor,
        total_count,
    )
    for convs, cursor, total_count in pages
]
```

And pad the page tuples **in the fixture** so both 2- and 3-wide call sites work:

```python
pages = [p + (None,) if len(p) == 2 else p for p in pages]
```

- Padding keeps the existing characterization call sites (2-tuples, e.g. `([], None)`)
  working **unedited** — they become `total_count=None` → estimate `None`, and no
  existing assertion looks at the new key. This is what keeps the characterization
  tests byte-identical (spec AC3).
- The client-total-count aspect may already have widened every call site to 3-wide;
  the padding is idempotent either way, so this aspect does not depend on which shape
  the fake's callers use. New estimate tests always pass an explicit third value.
- `_fake_client_with_parts` (:194-206) delegates to `_fake_client` — nothing to change
  there.

## 7. Edge Cases & Error Handling

| Case | Required behaviour |
|---|---|
| `total_count` absent from payload (`None`) | Estimate `None`; completed run writes `None` (explicit, overwrites stale — honest) |
| `total_count == seen` | `0` (int) — drained window; persists as `0` |
| `seen > total` (`>=` boundary re-fetch inflates seen) | `max(0, …)` → `0`, never negative (pinned test) |
| Empty run (no pages/conversations) | `seen == 0`; total 0 → `0`; total None → `None` |
| 20-page cap hit | Estimate computed from partial `seen` — honest for the window; cursor resumes next run; next run recomputes |
| `total_count` differs across pages (shouldn't — per-query constant) | Last page wins by construction; no assertion needed, loop overwrite is the pinned shape |
| Auth error (401/403) | `_persist_terminal_status("auth_error")` → `backlog_remaining = None`; D7 untouched (no disconnect, no retry) |
| Transient error (429/5xx/network) | `_persist_terminal_status("transient_error")` → `backlog_remaining = None`; `task_self.retry` unchanged; cursor not advanced (commit never ran) |
| OAuth / never-synced rows | Never run `_sync_org` → column stays NULL (db-status-api has no `server_default`) |
| Enrichment keys (`changed_feedback_ids`, `dropped_by_cap`) | Untouched — additive-key full-set assertion in Phase 1 #5 |
| Result dict consumers (`{"status": "ok", **result}`) | `backlog_remaining` flows into the task return automatically (OQ2) |
