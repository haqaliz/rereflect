## 6. Edge cases & error handling

- **null vs 0 vs undefined**: all hide the row (`null > 0` and `undefined > 0` are false). If a
  pre-db-status-api backend omits the key, the row silently never renders — the same
  required-field assumption the writeback fields already document (`intercom.ts:35-37`).
- **Large backlogs**: `toLocaleString()` renders "≈ 4,600 ..." for five-figure windows.
- **Zero-ingested + positive remaining**: impossible after a completed run in practice (seen
  conversations ≥ 1 whenever the window is non-empty) — the alert gate keeps even the transient
  overlap coherent.
- **Error-path staleness**: backend-owned (`_persist_terminal_status` resets to None, aspect 2);
  the frontend renders whatever the API sends.
- No hardcoded colors; the row reuses the existing dl/dt/dd classes.

## 7. Agent execution notes

- Land independently of the backend aspects — the mocked-API tests are the gate. End-to-end
  validation against the real backend only after `db-status-api` + `sync-estimate` land.
- Manual check (after both land): connect a workspace with a backlog, run pulls, confirm the
  row shows while remaining > 0 and disappears at 0; a failed run shows no row; OAuth/never
  synced show no row.

## Decisions & open questions

- **D1 — Alert gating exceeds the spec's letter** ("tighten the wording" only). Committed anyway:
  with a positive estimate visible, "That is expected if no one has written in since you
  connected" is factually false — exactly the dishonesty this feature exists to remove. The
  added condition is one line and pinned by the "alert hidden while backlog remains" test.
  Revertible to copy-only if reviewers object (drop the condition + that test).
- **D2 — Fixture semantics**: CONNECTED carries a positive estimate (137) so every connected
  test exercises the row; the zero-state test overrides `backlog_remaining: 0` for coherence
  (0 ingested + fully drained window is the alert's honest home).
- **S1 (PRD should-have, out of this aspect's scope)**: first-run framing ("window = since you
  connected") in the row copy. Trivially foldable into the dd if wanted ("...since you
  connected"); deferred per spec in-scope.
- **OAuth**: the frontend cannot distinguish OAuth from token-paste; the null branch covers it
  by construction (backend never produces a value for OAuth orgs).
