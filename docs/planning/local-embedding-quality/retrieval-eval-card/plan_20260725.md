# Implementation Plan — retrieval-eval-card (Aspect 3)

**Feature:** local-embedding-quality (M5.4) · **Aspect:** `retrieval-eval-card`
**Spec:** `./spec.md` · **PRD:** `../prd.md` · **Date:** 2026-07-25
**Branch:** `feat/local-embedding-quality` · **Depends on:** Aspects 1 (model key) + 2 (`local` provider), merged.
**Execution:** strict TDD. Sequenced to produce the REAL eval number early (it gates the model choice).

## 0. Summary & honesty stance
Mirror the M5.1 sentiment eval (`scripts/eval_sentiment.py` + `eval_results/*.json` + read-only
`/…/accuracy` endpoint + a frontend accuracy card). Here the domain is **retrieval**: does the copilot
template matcher pick the right template for a paraphrased question, and does it correctly reject a
question that matches no template?

- **Baseline:** `nomic-embed-text` via ollama (768-dim) — the current local default. Server is up in
  this env; model pulled.
- **Candidate:** in-process `local` / `BAAI/bge-small-en-v1.5` (384-dim).
- **Gate (PRD):** candidate **recall@1 ≥ baseline + 0.05** AND false-match rate on negatives **≤ baseline**.
  Like M5.1 the artifact is **disclosure, not a CI merge gate** (script always exits 0). But a
  sub-threshold result is **escalated to the human**, not silently shipped as "beats".
- **Fixtures MUST be held-out paraphrases** — NOT the 66 seeded `question_patterns` (those embed to
  ~1.0 and make the eval tautological). Author fresh paraphrases + realistic negatives.

## 1. Setup
- Service: `services/backend-api` (harness, fixtures, endpoint) + `services/frontend-web` (card).
- New artifact: `services/backend-api/eval_results/retrieval_accuracy.json` (committed once, real run).
- Deps: none new (sentence-transformers from Aspect 2; ollama external).
- Frontend is a **pnpm workspace** (repo memory) — use `pnpm`, not npm; `node_modules` is not installed
  in the worktree, so the frontend task must `pnpm install` first (or scope to type-check + the one test).

## 2. Fixture format (locked so Tasks 1 & 2 agree)
`services/backend-api/tests/fixtures/embedding_eval/queries.jsonl` — one JSON object per line:
```json
{"query": "how many bits of feedback have we collected in total", "expected": "Count total feedbacks"}
{"query": "what's the weather today", "expected": null}
```
- `expected` = the target template's **`description`** (stable, unique across the 15 — DB ids are not
  stable) for a positive; `null` for a negative (should match NO template).
- Keying on `description` avoids DB-id coupling; the harness maps description→template_id after seeding.

## 3. Tasks

### Task 1 — Held-out eval fixtures (≥60 pairs incl. negatives)
- **File:** NEW `tests/fixtures/embedding_eval/queries.jsonl` + a tiny `queries_tiny.jsonl` (≈6 rows) for
  fast unit tests.
- **Author:** for each of the 15 templates (descriptions in `template_saver.py:70-344`), 3 **held-out
  paraphrases** that a real user might type and that are NOT in that template's `question_patterns`
  (≈45 positives), PLUS ≥15 **negatives** — plausible product questions that match no template (e.g.
  "export all feedback to CSV", "who is assigned to this ticket", "change my password") and a few
  **hard negatives** near the known collision pairs (#7 churn-risk vs #12 declining-health; #4 pain-point
  category vs #13 severity; #3 urgent-list vs #15 urgent-categories) phrased to be genuinely ambiguous.
  Total **≥ 60** rows. Each `expected` is an exact template `description` or `null`.
- **AC:** a loader test asserts the file parses, every non-null `expected` matches one of the 15 real
  descriptions exactly (guards typos), ≥60 rows, ≥15 negatives, no paraphrase is a verbatim copy of any
  seeded `question_pattern` (assert disjoint).
- **Commit:** `test(local-embedding-quality): held-out retrieval eval fixtures`

### Task 2 — Eval harness (`scripts/eval_embeddings.py`, importable core + CLI)
- **File:** NEW `scripts/eval_embeddings.py`. Mirror `eval_sentiment.py` conventions (importable core, CLI,
  **always exit 0**, honest).
- **Core:**
  - `load_fixtures(path) -> list[dict]` (jsonl).
  - `build_resolved_embedder(provider, *, base_url=None, model=None) -> ResolvedEmbedder` — wrap
    `EmbeddingProviderFactory.create(...)` (no DB/OrgAIConfig needed).
  - `run_provider(resolved, fixtures, db) -> ProviderRetrievalResult`: seed templates for this provider
    into `db` (`TemplateSaver().seed_system_templates(db, embedder=resolved)`); build a description→id map;
    for each fixture call `TemplateMatcher().find_match(query, org_id, db, embedder=resolved, threshold=0.85)`;
    score: **recall@1** (top match's description == expected), **MRR** (rank of the gold template among all
    templates by similarity — compute a full ranking, not just best, so MRR is meaningful), **false-match
    rate** on negatives (fraction of `expected==null` that returned a non-None match ≥0.85). Track n_pos,
    n_neg.
  - `compare(baseline, candidate) -> {recall_at_1_delta, meets_target(bool = delta>=0.05 and
    candidate.false_match_rate <= baseline.false_match_rate)}`.
  - `run_eval(fixtures, providers: dict) -> artifact dict`.
- **Artifact** `eval_results/retrieval_accuracy.json` (mirror sentiment shape):
  ```json
  {"generated_at": "<iso>", "candidate_model": "BAAI/bge-small-en-v1.5",
   "baseline_model": "nomic-embed-text", "n": <int>, "n_negatives": <int>,
   "baseline": {"provider":"ollama","model":"nomic-embed-text","recall_at_1":..,"mrr":..,"false_match_rate":..,"n":..},
   "candidate": {"provider":"local","model":"BAAI/bge-small-en-v1.5", ...},
   "recall_at_1_delta": <float>, "meets_target": <bool>}
  ```
  `datetime.now(timezone.utc)` is fine in a script (NOT in a workflow); default `--output` =
  `services/backend-api/eval_results/retrieval_accuracy.json`; `makedirs` + `json.dump(indent=2)`.
- **DB for the harness:** use a scratch SQLite session (create_all) or the test `db` fixture — seed both
  providers into it (Aspect-1 model key keeps their vectors from cross-matching). A default `org_id` (1)
  suffices; system templates are org-less.
- **Tests (unit, offline, deterministic):** use a STUB embedder (fixed vectors) so `run_provider`/metrics
  are tested without real models — assert recall@1/MRR/false-match math on a crafted tiny fixture +
  known vectors; assert `meets_target` logic; assert the script's core never raises on an empty/степ
  fixture. Do NOT require ollama/bge in unit tests.
- **Commit:** `feat(local-embedding-quality): retrieval eval harness (recall@1/MRR/false-match)`

### Task 3 — Produce the committed artifact (REAL run) + gate check
- **Not a code task** in the usual sense — RUN the harness live: ollama `nomic-embed-text` (baseline) vs
  in-process `bge-small-en-v1.5` (candidate) over the full fixtures; commit
  `eval_results/retrieval_accuracy.json`.
- **Report the number.** If `meets_target` is TRUE → proceed. If FALSE → **STOP and escalate to the
  human** (the candidate doesn't clear recall@1 ≥ baseline+0.05 or regresses false-match): options are
  (a) pick a different local default model — change ONLY `LocalEmbeddingProvider.DEFAULT_MODEL`, re-run;
  (b) ship it honestly labeled "does not currently beat baseline" (disclosure stance); (c) adjust scope.
  Do NOT massage fixtures to force a pass.
- **Commit:** `chore(local-embedding-quality): commit retrieval eval artifact (bge-small vs nomic)`

## 4. Sequencing / checkpoints
- Order: Task 1 → Task 2 → **Task 3 (get the number — checkpoint/escalate if it fails the gate)** →
  Task 4 → Task 5. Tasks 4 & 5 build the disclosure UI around a known-honest result.
- **Human checkpoint after Task 3** if `meets_target` is False.

## 5. Edge cases
- ollama down at run time → baseline provider errors; harness records baseline as unavailable rather than
  crashing (still writes candidate numbers, `meets_target=null`, labeled honestly). Report it.
- Negatives that legitimately match a template (mis-authored) would inflate false-match — the fixture
  review (Task 1) must keep negatives genuinely out-of-scope.
- Seeding both providers into one DB: rely on Aspect-1's `(provider,dim,model)` key so vectors don't
  cross-match; give each provider its own seed pass.
- `find_match` normalizes/strips stopwords — author paraphrases in natural language; the harness uses the
  production path, so normalization is included (good — realistic).

## 6. Agent execution notes
- Task 1 (fixtures) is judgment-heavy: the reviewer must check for tautology (no verbatim seeded
  patterns), realistic negatives, and that hard-negatives are genuinely ambiguous — not gibberish.
- Task 3 is where honesty bites: report the true number; escalate a miss, don't tune fixtures to pass.
- Keep the eval "always exit 0 / disclosure not gate" stance from M5.1.
