# Implementation Plan — ollama-default-bump (Aspect 5)

**Feature:** local-embedding-quality (M5.4) · **Aspect:** `ollama-default-bump`
**Spec:** `./spec.md` · **PRD:** `../prd.md` (Option B, should-have) · **Date:** 2026-07-25
**Branch:** `feat/local-embedding-quality` · **Depends on:** Aspect 3 (eval harness).
**Execution:** eval runs (me) + a docs-only recommendation. No code change.

## 0. Summary & decisions
Make the recommended Ollama embedding model (for operators who run the external Ollama server path)
**eval-backed** instead of asserted. Re-use the Aspect-3 harness to score candidate Ollama models
(`mxbai-embed-large`, `bge-m3`) against the current default `nomic-embed-text`, then recommend the
winner in `docs/SELF_HOSTING.md`.

- **Docs-only (PRD Q1 default stance):** do NOT change `_default_embedding_model('ollama')` (or the
  factory/defaults literals) — that would be a behaviour change for existing ollama installs (triggers
  a reseed via the model key). Keep the code default `nomic-embed-text`; recommend the better model in
  the docs with the `ollama pull` command. (Changing the code default is only on explicit user approval.)
- **Do NOT overwrite the committed `eval_results/retrieval_accuracy.json`** — that is the primary
  `bge-small`(local) vs `nomic`(ollama) story. The Aspect-5 ollama-vs-ollama numbers go into the docs
  recommendation only (informational), produced with `--output` to a scratch path.

## Task 1 — Run the informational evals (controller runs directly)
For each candidate ollama model available:
```
./venv/bin/python scripts/eval_embeddings.py \
  --baseline-provider ollama --baseline-model nomic-embed-text \
  --candidate-provider ollama --candidate-model <mxbai-embed-large|bge-m3> \
  --output /tmp/ollama_eval_<model>.json
```
Record recall@1, MRR, false_match_rate for nomic (baseline) and each candidate, and the deltas. Honesty:
if a model can't be pulled/run in this env, record what was and wasn't measured; do not assert a winner
without numbers.

## Task 2 — Docs recommendation (SELF_HOSTING) — dispatched with the real numbers
- In `docs/SELF_HOSTING.md`, in the existing "Fully-local LLM / Copilot" Ollama section (where
  `ollama pull nomic-embed-text` is documented, ~line 125-129), add an eval-backed note: for stronger
  Copilot template matching on the Ollama path, the operator may use `<winning model>` (with the
  `ollama pull <model>` command), citing the measured delta and `n`, AND the resource-cost caveat
  (bigger models — e.g. mxbai-embed-large 1024-dim / bge-m3 — cost more RAM/latency on the operator's
  Ollama server). Note that switching models re-embeds the built-in templates automatically (Aspect-1
  model key), so it's safe.
- Keep it honest: if the "better" model only marginally beats nomic (or doesn't), say so; the in-process
  `local` provider (bge-small) remains the primary recommended offline path.
- Optionally add a one-line CHANGELOG note that the Ollama embedding recommendation is now eval-backed.

## Sequencing / notes

- Absolutely no code / no committed-artifact change. If neither candidate clears a meaningful margin
  over nomic, the honest outcome is "nomic-embed-text remains a fine default; `local`/bge-small is the
  recommended upgrade path" — that's a valid, non-failing result (disclosure stance).
- This is a should-have; the substantive M5.4 feature is already COMPLETE (Aspects 1-4).
