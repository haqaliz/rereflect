## Testing Strategy

- Unit: Phase 1 tests (ciphertext on write, plaintext on read, 4xx on corrupt/missing key).
- Key: **missing-key tests must patch the env explicitly** (`@patch.dict(os.environ, {"LLM_ENCRYPTION_KEY": ""})`) — do not rely on the repo `.env` being present in CI.
- Run: `cd services/backend-api && pytest tests/ -v`.

## Environment & Secrets

- `LLM_ENCRYPTION_KEY` must be set for tests that hit encrypt/decrypt — either present in `services/backend-api/.env` (loaded via `load_dotenv` in `src/api/auth.py`/`src/database/session.py`) or patched. Prefer explicit `patch.dict` in the new error-path tests; the happy-path tests can use the repo's existing key.
- No external services to configure.

## Edge Cases & Error Handling

- Corrupt ciphertext (key rotation, mismatched dump): `InvalidToken` → 400 actionable, never 500.
- Missing key at write: 422 (mirrors Zendesk).
- Missing key at read: 4xx actionable, never 500.
- Truthiness guards unchanged: existing `if not integration.oauth_access_token` checks still pass for ciphertext (non-empty).
- No double-decrypt: decrypt happens once per request at the call site; `send_slack_message_oauth` takes the token as an argument and never re-reads the DB.
