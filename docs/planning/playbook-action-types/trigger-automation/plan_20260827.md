### Phase 3 — `_handle_trigger_automation` (GREEN)

**Goal:** the tests pass with the real seam.

**Files:**
- `src/services/playbook_engine.py` (modify)

**Steps:**
1. Read `automation_churn_trigger.py` fully (esp. `_evaluate_rule` :164-214, `_check_cooldown`
   and `_set_cooldown` :80-112) so the reuse is exact. **Do not modify it.**
2. Implement `_handle_trigger_automation(config, customer_email, health, db)`:
   - `name = (config.get("automation_name") or "").strip()`; empty → `ok: False`
   - query `AutomationRule` (worker mirror, `src/models/automation_rule.py`) by
     `organization_id == health.organization_id` + `name == name`,
     `order_by(created_at, id)`; none → `ok: False, f"no rule named '{name}'"`
   - `mode != "active"` → `ok: False, f"rule '{name}' found but mode={mode} — not fired"`
   - `trigger_type != "churn_probability_threshold"` → `ok: False` with the seam reason
     (`"usage_trend"` → `f"trigger type 'usage_trend' fires only from the daily recompute seam"`
     else `f"trigger type '{t}' fires only from its native evaluator"`)
   - `cooldown_hours < 1` → `ok: False, f"rule '{name}' has cooldown_hours < 1 — refused"`
   - `health.churn_probability is None` → `ok: False, "no churn probability available for customer"`
   - else call `automation_churn_trigger._evaluate_rule(rule, rule.organization_id,
     customer_email, float(health.churn_probability), db)` inside `try/except`
     (never raise — `ok: False` on exception) and return
     `{"ok": True, "result": {"fired": True, "rule_id": rule.id, "automation_name": name}}`
3. Add the `_dispatch_action` branch.
4. Run the full suite; all new tests green, nothing else moved.

**Validation:** `pytest tests/test_playbook_trigger_automation.py tests/test_playbook_engine.py tests/test_automation_churn_trigger.py tests/test_usage_trend_churn_boundary.py -q`

## 5. Edge Cases & Error Handling

- Name with surrounding whitespace → trimmed; empty → refused
- Two rules with the same name → first by `created_at, id`; `rule_id` reported
- `_evaluate_rule` raising → caught, `ok: False`, run continues
- Rule's own threshold/cooldown logic is authoritative (AC2/AC3 — the handler never
  duplicates the threshold check; it delegates)
