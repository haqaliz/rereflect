## 2. Decisions (settle here, per PRD OQ3/OQ4 + the specs)

- **Customer-email column identification:** name-match. A column whose lowercased name is `customer_email` (or `email`) is the cohort column. Simple, sufficient for slice 1; the SQL results' columns come from the whitelisted schema where the email column is `customer_email`. Schema-derived detection is a later refinement (noted in the spec's open question).
- **Minimum rows:** offer the action for **1..cap** unique emails. This intentionally differs from `include_table`'s `row_count >= 2` gate — a single-row result renders no table but can still offer an action, which is exactly the frame-emission behavioural change the spec requires to be pinned (`deterministic-proposer/spec.md:50-52`).
- **Email cap:** `ACTION_EMAIL_CAP = 200`. **Correction to the PRD:** `MAX_TABLE_ROWS` in `response_formatter.py:24` is **1000**, not the 50 the PRD guessed (OQ4) — so the action cap must be its own, lower constant. 200 is deliberately under the 500 bulk endpoints use elsewhere and keeps the frozen cohort embedded in `structured_data` JSON reasonable. A result over the cap offers **no** action (never a silent truncation).
- **`proposal_id` derivation:** `f"{message_id}:tag_customers:{sha1('|'.join(emails).encode()).hexdigest()[:6]}"`. Deterministic for the same message + cohort (fixture's `"msg-42:tag_customers:3f9a1c"`). Opaque to the execute route — the one-shot guard keys on the full string (PRD OQ2); the embedded `message_id` part is never parsed at execute time.

## 6. Edge Cases & Error Handling

- No email column → no actions item, `structured_data` identical to today.
- Zero rows → no actions item.
- Over-cap (200) → no actions item (never truncated).
- Duplicate emails across rows → deduped in the frozen cohort.
- `general`/`report` intents → never reach the proposer (guard at line 555; `report` early-returns at 466-495).
- `structured_data` is **not sanitised** at any layer — the item carries only server-derived org data (emails), rendered as text by the frontend aspect.
- The frame-emission change (empty list → non-empty) is intended and pinned by the single-row test; clients see a `structured_data` frame where today they would see none.
