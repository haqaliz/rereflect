## 2. Implementation Phases

### Phase A — Extract the tag-apply logic into a shared service (characterization-first)

**Goal:** the set-union/difference tag application (`customers.py:708-729`) becomes a callable service the registry can reuse without an internal HTTP request, with the existing route byte-behaviourally unchanged.

**Prerequisites:** none.

**Files:**
- Create `services/backend-api/src/services/customer_tags.py`
- Modify `services/backend-api/src/api/routes/customers.py`

**Steps:**
1. **RED first (TDD):** write a characterization test `services/backend-api/tests/test_customer_tags.py` that drives the new `apply_tags` service directly across the behaviours the route currently pins in `tests/test_customers_bulk.py`: set-union add, set-difference remove, deterministic `sorted()` output, the 20-tag cap putting the row into `errors` (row unchanged, not counted in `updated`), empty/de-duped input handling. These tests fail while `apply_tags` does not exist.
2. **GREEN:** create `services/backend-api/src/services/customer_tags.py`:
   - Move the two constants (`_TAG_MAX_LENGTH = 50`, `_TAG_CAP_PER_CUSTOMER = 20`, today `customers.py:655-656`) into this module as module-level `TAG_MAX_LENGTH` / `TAG_CAP_PER_CUSTOMER`, imported back by `customers.py` (keep names non-private so both modules share one definition).
   - `def apply_tags(rows: List[CustomerHealth], tags: List[str], mode: Literal["add", "remove"]) -> Tuple[int, List[str]]` — verbatim port of the loop at `customers.py:713-725`: `existing = set(record.tags or [])`; union (`add`) or difference (`remove`) by `mode`; if `len(new_tags) > TAG_CAP_PER_CUSTOMER` append the exact error string (`f"{record.customer_email}: would exceed the {TAG_CAP_PER_CUSTOMER}-tag limit ({len(new_tags)} after applying) — not updated"`) and `continue`; else `record.tags = sorted(new_tags)`; return `(updated, errors)`. **Do not commit inside the service** — the route keeps the single `db.commit()` (all-or-nothing per request; `log_action` commits independently, that is fine).
3. **REFACTOR the route:** in `customers.py` `bulk_tag_customers`, replace lines 709-726 with `updated, errors = apply_tags(rows, body.tags, body.mode)` and keep `db.commit()` + the return. Do **not** move the Pydantic validation (`BulkTagRequest._clean_tags`) — validation stays in the schema (422 before the handler), the service starts from already-cleaned tags.
4. Run the full existing suite: `tests/test_customers_bulk.py` (RBAC, add/remove, cap-to-errors, scope/skipped) must stay green unchanged — that is the characterization net proving the extraction changed nothing.

**Validation:** `pytest tests/test_customers_bulk.py tests/test_customer_tags.py -v` green; route behaviour identical (existing tests untouched).

**Commit message:** `refactor(copilot-actions): extract shared tag-apply service (characterization-tested)`

### Phase B — The registry (RED → GREEN)

**Goal:** `src/services/copilot/action_registry.py` — the only dispatch path. Unknown action ids are rejected before anything runs; `min_role` is enforced by the registry at execute time, independent of the route's own dependency.

**Prerequisites:** Phase A.

**Files:**
- Create `services/backend-api/src/services/copilot/action_registry.py`
- Create `services/backend-api/tests/test_action_registry.py`

**Steps:**
1. **RED:** write `tests/test_action_registry.py` first:
   - Unknown `action` id → `UnknownActionError` (or 404-equivalent), nothing executed.
   - Entry lookup by id returns the entry.
   - `min_role` check: member → denied (403-equivalent), admin/owner → allowed. Use a `role_level` map `{"member": 1, "admin": 2, "owner": 3}`; an entry with `min_role="admin"` allows admin+owner only.
   - **Registry-drift guard (spec's risk table):** a test that walks `ACTION_REGISTRY` and asserts every entry's `min_role` is at least as strict as its executor route's dependency. For `tag_customers` the executor is `POST /customers/bulk/tags` = `require_admin_or_owner` → assert `role_level(entry.min_role) >= 2`.
2. **GREEN:** implement `action_registry.py`:
   - `ActionEntry` dataclass: `action_id: str`, `min_role: str`, `executor: Callable`, `params_validator: Callable` (or a Pydantic model).
   - `ACTION_REGISTRY: Dict[str, ActionEntry]` containing exactly `tag_customers`.
   - `get_entry(action_id) -> ActionEntry` — raises `UnknownActionError` on miss.
   - `require_role(entry, user) -> None` — raises `InsufficientRoleError` (403) when `role_level(user.role) < role_level(entry.min_role)`.
   - `tag_customers` executor signature: `executor(db, org, *, emails: List[str], tag: str) -> BulkActionSummary` — internally calls `cohort_service.resolve_cohort(db, org, Cohort(emails=emails))` then `customer_tags.apply_tags(rows, [tag], "add")`, returns `BulkActionSummary(matched=len(rows), updated=updated, skipped=skipped, errors=errors)`.
   - Export `COPILOT_ACTION_AUDIT_ACTION = "copilot_action_executed"` for the route + one-shot guard.

**Validation:** `pytest tests/test_action_registry.py -v` green.

**Commit message:** `feat(copilot-actions): whitelisted action registry with min_role enforcement`

### Phase C — The execute route (RED → GREEN)

**Goal:** `POST /api/v1/copilot/actions/execute` — authenticated, org-scoped, registry-validated, min_role-enforced, one-shot-guarded, audited. Returns `BulkActionSummary`.

**Prerequisites:** Phase B.

**Files:**
- Create `services/backend-api/src/api/routes/copilot_actions.py`
- Modify `services/backend-api/src/api/main.py` (register the router — after `copilot.router` at line 391; router carries its own `/api/v1/copilot` prefix so no ordering hazard with the `/{email}` wildcard on customers)
- Create `services/backend-api/tests/test_copilot_actions_execute.py`

**Steps:**
1. **Decisions (settle in this phase, per PRD OQ1/OQ2):**
   - Namespace: **`/api/v1/copilot/actions/execute`** (leaning in `prd.md:203`; `copilot.py` holds only `GET /usage`).
   - Request body `ExecuteActionRequest{conversation_id: int, proposal_id: str, action: str, params: Dict[str, Any]}`.
   - **The cohort is the frozen proposal, never the client.** Emails come from the proposal's `params.emails` embedded in the persisted message (M9); the client supplies **only** the tag (`requires_input: ["tag"]`).
   - **One-shot guard keyed on `proposal_id` alone** (PRD OQ2): never on the WS wire `message_id`. Look up prior successful executions by `AuditLog.details["proposal_id"]`.
2. **RED:** write `tests/test_copilot_actions_execute.py` from the spec's acceptance criteria:
   - Unknown `action` id → 404, nothing executed, nothing audited.
   - `member` JWT → 403, nothing executed, nothing audited.
   - Admin, valid params, proposal present → tags applied, `BulkActionSummary` returned, exactly one `AuditLog` row.
   - Foreign/unknown emails in the frozen cohort → absorbed as `skipped`, reported, never an error, never a cross-org write.
   - Same `proposal_id` executed twice → second call does **not** re-execute and does **not** write a second `AuditLog` row; the prior outcome is returned.
   - Tag over 50 chars → 422, nothing applied.
   - Customer already at 20 tags → that row in `errors[]`, others still update.
   - `proposal_id` not matching any proposal on any message of `conversation_id` → 404.
   - Empty/whitespace tag → 422.
   - Cross-org `conversation_id` → 404 (conversation lookup is org-scoped).
3. **GREEN:** implement `copilot_actions.py`:
   - `router = APIRouter(prefix="/api/v1/copilot", tags=["copilot-actions"])`.
   - `@router.post("/actions/execute", response_model=BulkActionSummary, dependencies=[Depends(get_current_user), Depends(get_current_org)])` — deliberately **no** `require_admin_or_owner` at route level; RBAC is the registry's `min_role` (the pattern the spec wants for future actions).
   - **Proposal lookup:** load `Conversation` by `conversation_id` scoped to `org.id` (404 if missing); iterate `conversation.messages`; for each message with `structured_data`, scan the items array for an item with `item["data_type"] == "actions"` and `item["data"]["proposal_id"] == proposal_id`; also confirm the item's actions array contains the requested `action`. No match → 404 `"proposal not found"`.
   - **Registry:** `entry = get_entry(body.action)` (404 `UnknownActionError`); `require_role(entry, current_user)` (403).
   - **Frozen cohort + user params:** `emails = proposal_item["data"]["actions"][matching_action]["params"]["emails"]`; `tag = str(body.params.get("tag", "")).strip()`; empty or `len(tag) > TAG_MAX_LENGTH` → 422. (Mirror `BulkTagRequest._clean_tags` semantics for the single tag.)
   - **One-shot guard:** query `AuditLog` where `organization_id == org.id`, `action == COPILOT_ACTION_AUDIT_ACTION`, `target_type == "copilot_action"`, and `details["proposal_id"].astext == proposal_id` (JSON subscript + `.astext` works on Postgres JSONB and SQLite JSON1). If a prior row with a stored `details["outcome"]` exists, return that stored `BulkActionSummary` (parse `details["outcome"]`) without executing.
   - **Execute:** `result = entry.executor(db, org, emails=emails, tag=tag)`.
   - **Audit:** `audit_service.log_action(db, org_id=org.id, user_id=current_user.id, user_email=current_user.email, action=COPILOT_ACTION_AUDIT_ACTION, target_type="copilot_action", target_id=<the ConversationMessage.id that carried the proposal>, details={"proposal_id": proposal_id, "action": action, "tag": tag, "outcome": result.model_dump()}, request=request)`. `log_action` commits itself (`audit_service.py:55-57`) — call it **after** the executor's `db.commit()` so a failed executor never leaves an audit row claiming success.
   - Return `result`.
4. Register in `main.py`: import `copilot_actions` and `app.include_router(copilot_actions.router)` after line 391.

**Validation:** `pytest tests/test_copilot_actions_execute.py tests/test_action_registry.py tests/test_customer_tags.py tests/test_customers_bulk.py -v` green. Then `pytest tests/ -v` (full backend suite) — must stay green (no route-registration regression, single alembic head).

**Commit message:** `feat(copilot-actions): execute route for suggested actions (registry-gated, one-shot, audited)`

## 5. Environment & Secrets

- None new. Tests run on SQLite in-memory; the `.astext` JSON filter must pass on SQLite (JSON1) — if it fails in CI on Postgres, it is a SQLAlchemy JSON-subscript portability issue; the fallback is a Python-side filter over the org's `copilot_action` audit rows (low volume, acceptable per spec). Decide in Phase C with the failing test, not by guessing.

## 6. Edge Cases & Error Handling

- Unknown action / unknown proposal / cross-org conversation → 404, nothing executed, nothing audited.
- Member → 403 via `require_role`, nothing audited.
- Tag validation → 422 (empty after strip, >50 chars). Tag is single-valued (slice 1, `mode="add"` only).
- Per-customer 20-tag cap → that row in `errors[]`, other rows still update; the whole request still commits (`apply_tags` returns errors, route commits).
- Foreign emails in the frozen cohort → `resolve_cohort` counts them `skipped`; never raised (`cohort_service.py:48`).
- Double-execute → one-shot guard returns the stored prior outcome, no second audit row.
- **Worker duplication is intentional and untouched:** `worker-service/src/services/playbook_engine.py:525-575` mirrors `_handle_tag` with its own copies of the 50/20 constants — it cannot import the backend service (repo CLAUDE.md). Do **not** try to share it; the constants drift risk is documented, not fixed here.
- `log_action` self-commits — call it after the executor commit so failure never leaves a false-success audit row.
