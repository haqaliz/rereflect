## 2. Resolved ambiguity — read before coding

**The spec says `off | shadow | active`. The neighbouring columns on the same table say
`off | shadow | auto`** (`VALID_CLASSIFIER_MODES = {"off","shadow","auto"}`,
`services/backend-api/src/api/routes/ai_settings.py:45`, used by `classifier_mode`,
`category_classifier_mode`, `urgency_classifier_mode`).

**Decision: use `active`, not `auto`.** Rationale: those three columns gate a *classifier* that
auto-applies a prediction; this column gates *writing rows into an operator's review queue*, which is
the same semantics as `AutomationRule.mode` (`off|shadow|active`), the pattern M3.2c and M4.1.5 both
shipped. The PRD locked `active`.

**Two consequences the agent MUST honour:**
1. **Define a new constant** — `VALID_USAGE_CHURN_LABEL_MODES = {"off", "shadow", "active"}`.
   **Do not reuse `VALID_CLASSIFIER_MODES`**; it would silently accept `auto` and reject `active`.
2. **Do not call `_classifier_deps_available()`** in this validation block. The three classifier
   blocks call it because they need scikit-learn. **This feature needs no ML dependency at all** —
   copying that guard would make the setting un-settable on a lean install for no reason.

## 6. Edge Cases & Error Handling

| Case | Required behaviour |
|---|---|
| Org has **no** `OrgAIConfig` row | Read returns `'off'`; do not 500 (mirror the existing `if config else` idiom) |
| `usage_churn_labels_mode: null` explicitly sent | Allowed; treated as `'off'` by readers (matches sibling columns' NULL semantics) |
| `"auto"` sent (the sibling-column value) | **422** — deliberate; pinned by test |
| `sustain_days: true` | **422** — `bool` is an `int` subclass; must be rejected explicitly |
| Unknown key in `usage_churn_label_config` | **422** — fail loudly rather than silently ignore a typo'd knob |
| Multi-tenancy | The route already resolves `OrgAIConfig` by the JWT's `organization_id`; **add no new lookup path** |
| Migration on a DB with existing rows | `server_default='off'` backfills; existing columns must be byte-identical (Phase 4) |
