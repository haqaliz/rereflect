## Plan-level discovery (flagged to the user at the review gate)

The dig found the bug in `churn_calibration.py`. **Planning-time verification found the
same bug class in `classifier_training.py`**: `retrain_all_orgs` (beat
`retrain-classifier-weekly`, 06:30 Mon — the M5.2 self-improving classifier refit) is
also an undecorated plain function, and the file has no celery import at all. The
existing guard `test_beat_schedule_integrity.py::test_beat_entry_resolves_to_a_real_task`
only asserts `hasattr(module, attr)` — an undecorated function passes while Celery
dispatch raises `NotRegistered`. **This aspect therefore fixes both files and hardens the
guard.** Scope-widening is small, contained, and directly serves the PRD goal ("the
incumbent actually runs"); vetoing it means restricting aspect 1 to churn_calibration.py
only and leaving the M5.2 refit dead.

**Amendment (2026-08-14, integrator-approved after RED):** the hardened guard also caught
a FIFTH entry of a different failure class: `churn_playbooks.py:65` decorates
`purge_old_executions` as `@shared_task(name="tasks.churn_playbooks.purge_old_executions")`
— the explicit `name=` lacks the `src.` prefix while the beat entry (`celery_app.py:208`)
uses `src.tasks.churn_playbooks.purge_old_executions` → dispatch raises `NotRegistered`
and the 90-day playbook-execution purge has never run. The `celery_app.py:195-197`
comment claims the entry was repaired; only the beat side was — the task-name side still
mismatches. Folded into this aspect (one string + a registration-name test), because the
hardened guard cannot go green without it.

## 2. Implementation phases

### Phase 1 — RED: harden the guard, prove both files fail

- **Goal**: a test that fails on the current code, proving the registration bug.
- **Prereqs**: none.
- **Files**: `services/worker-service/tests/test_beat_schedule_integrity.py`
- **Steps**:
  1. In `test_beat_entry_resolves_to_a_real_task`, after `importlib.import_module(module_path)`,
     add: `assert task_path in celery_app.tasks, (...)` — an undecorated function never lands
     in `celery_app.tasks`, so this fails for both `churn_calibration` and `classifier_training`
     entries today. Import the module first so the registry lookup is order-independent
     (the file's docstring explains why this matters — keep that reasoning).
  2. Run: `pytest tests/test_beat_schedule_integrity.py -q` → expect the new assertion to
     fail for `refit-churn-calibration-weekly`, `refit-global-calibration-daily`,
     `purge-old-calibration-models`, `retrain-classifier-weekly`.
- **Validation**: the four above-mentioned entries fail; no unrelated entry fails
  (if any other beat entry is also unregistered, STOP and report — do not paper over).
- **Commit**: `test(worker): RED — beat entries must be registered Celery tasks, not bare functions`

### Phase 2 — GREEN: decorate the tasks

- **Goal**: all beat entries resolve to real registered tasks.
- **Prereqs**: Phase 1 (failing test).
- **Files**: `churn_calibration.py`, `classifier_training.py`
- **Steps**:
  1. `churn_calibration.py`: add `from celery import shared_task`; decorate
     `refit_all_orgs`, `refit_global_calibration`, `purge_old_calibration_models` with
     `@shared_task(name="src.tasks.churn_calibration.<name>")` (exact names per
     `celery_app.py:213,225,230`). No body changes.
  2. `classifier_training.py`: add the same import; decorate `retrain_all_orgs` with
     `@shared_task(name="src.tasks.classifier_training.retrain_all_orgs")`. No body changes.
  3. Delete the stale NOTE at `usage_metrics.py:482-485`.
  4. Run the full worker suite.
- **Validation**: `pytest tests/ -q` in `services/worker-service` green, including
  `test_churn_calibration_tasks.py` (direct-call tests unchanged) and the hardened
  integrity test.
- **Commit**: `fix(worker): register churn calibration + classifier refit beat tasks (were NotRegistered)`
