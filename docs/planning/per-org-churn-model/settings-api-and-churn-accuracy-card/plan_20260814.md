## 2. Implementation phases (strict TDD)

### Phase 1 — RED: settings API accepts churn mode

- **Files**: `ai_settings.py` + schemas, `test_ai_settings_churn_mode.py`
- **Steps**: test `PATCH /api/v1/settings/ai {"churn_classifier_mode": "shadow"}` persists
  and returns it; `"bogus"` → 422; mode `auto`/`shadow` with sklearn unavailable
  (`_classifier_deps_available` False) → 422; `off` always accepted → add the field to
  response/update + a validation block mirroring the existing three (identical guard).
- **Validation**: new + existing settings tests green; `pytest tests/ -q` (backend).
- **Commit**: `feat(api): churn_classifier_mode in AI settings (TDD)`

### Phase 2 — RED: classifier_accuracy accepts classifier_type=churn

- **Files**: `classifier_accuracy.py`, `test_classifier_accuracy_churn.py`
- **Steps**: extend `VALID_CLASSIFIER_TYPES` + `_HOLD_COLUMN_BY_TYPE["churn"]`; tests:
  accuracy card (empty state without model; incumbent-vs-challenger card with a seeded
  org churn model + eval run), versions list, rollback (reactivate-prior, disable-only,
  404, RBAC admin/owner, cross-org 404), resume clears `churn_autopromote_hold`,
  `decision='held'` surfaced.
- **Validation**: route tests green; existing sentiment/category/urgency tests unchanged.
- **Commit**: `feat(api): classifier_type=churn in accuracy/versions/rollback/resume (TDD)`

### Phase 3 — GREEN: frontend

- **Files**: `AISettingsGeneral.tsx`, `ClassifierAccuracyCard.tsx` (TYPE_COPY + card label),
  `settings/ai/page.tsx`, `AIReadinessCard.tsx` (target if moved), api client types
- **Steps**:
  1. Mode toggle (off/shadow/auto) for churn in the General tab, mirroring the existing
     three; hidden/degraded when the API lacks the field (defensive).
  2. Fourth `<ClassifierAccuracyCard classifierType="churn" />` on the Accuracy tab;
     TYPE_COPY entry ("Churn model"); honest copy: n shown, "promoted only when
     measurably better", provenance line ("incumbent: calibrated heuristic"), empty
     state mirrors `ModelAccuracyCard` ("No qualifying org yet — labels/target").
  3. Readiness card target/numeral from the aspect-2 verdict (if the target moved).
- **Validation**: `pnpm test` + `pnpm lint` in `services/frontend-web`; page test asserts
  exactly four classifier cards; component test pins empty/held/promoted states.
- **Commit**: `feat(ui): churn classifier mode toggle + accuracy card + readiness`

## 6. Edge cases & error handling

- API without the field (older backend) → toggle hides/degrades defensively.
- No model/no eval runs → empty state, not an error.
- Rollback with nothing active → 404 (unchanged semantics), surfaced as a toast.
