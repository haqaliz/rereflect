## 2. Implementation phases

### Phase 1 — RED: route contract test for the artifact readout

- **Goal**: `GET /api/v1/settings/ai/churn/label-gate` contract pinned before the script exists.
- **Files**: `tests/test_churn_label_gate_route.py`, `src/api/routes/churn_label_gate.py`, `src/api/main.py`
- **Steps**:
  1. Test: authenticated user gets 200 with `{artifact_version, verdict, target, method,
     n_simulations, honest_limits, generated_at}` when the artifact exists; 200 with an
     explicit empty state when the artifact file is absent (mirror
     `test_sentiment_accuracy_route.py`'s absent-file handling); org-scoped (org from JWT,
     no cross-org data — the artifact is a static file, so scope is trivially satisfied).
  2. Route: `get_churn_label_gate` reads `eval_results/churn_label_gate.json` via the
     same relative path pattern as `sentiment_accuracy.py:32`; never raises; never trains.
  3. Register in `main.py` under the settings router (mirror `sentiment_accuracy`).
  4. Run route test RED against the absent artifact → implement the empty-state path.
- **Validation**: route tests green; `GET` returns empty state before the script runs.
- **Commit**: `feat(api): churn label-gate readout route (RED: empty state)`

### Phase 2 — GREEN: the measurement harness + committed artifact

- **Goal**: a reproducible study whose verdict is recorded and committed.
- **Files**: `scripts/eval_churn_label_gate.py`
- **Steps**:
  1. CLI (`--simulations`, `--seed`, `--output`; defaults fixed) with an importable core
     (eval_sentiment.py pattern). Always exits 0 (disclosure, not a gate — matching the
     eval harness convention).
  2. Data-generating process (documented in the script docstring): simulate per-org churn
     datasets at label volumes `[20, 50, 100, 200, 300, 500, 800, 1200]` — customers with
     a feature vector (draw from realistic ranges per the `customer_health_scores` /
     `customer_usage` fields documented in the core spec; vary signal strength and class
     balance across two or three scenario families), labels generated by a hidden ground
     truth, churned fraction tuned to the org's window semantics
     (`_LABEL_WINDOW_DAYS=180` from `calibration_refit.py:40`).
  3. Challenger stand-in: sklearn `LogisticRegression` (same family the core will ship),
     leakage-free stratified holdout; incumbent stand-in: the calibrated-heuristic shape
     (a monotone transform of `churn_risk_component`, the identity/calibration family).
     Report `macro_f1_delta` (challenger − incumbent) per volume with CI across
     `--simulations` runs (fixed seed list).
  4. Also run a **feature-reconstruction fidelity dimension** (R3): re-evaluate the
     challenger when X% of feature rows are missing snapshots (defaulted) — report how
     the crossover point moves.
  5. Generate `eval_results/churn_label_gate.json` (fields: `verdict`, `target` (keep 500 /
     new number / "no defensible gate"), `method`, `n_simulations`, `crossover_label_volume`,
     `fidelity_sensitivity`, `honest_limits`, `generated_at`). **Run it for real**, review
     the numbers, and write the verdict — do not fabricate.
  6. Record the decision in `docs/planning/per-org-churn-model/prd.md` Decision Record
     (and apply to `readiness_thresholds.py`/`ai_readiness.py`/`AIReadinessCard.tsx` iff the
     target moves).
- **Validation**: script rerun with the same seed reproduces the artifact byte-for-byte
  (or documented delta only in `generated_at`); route test now returns the real payload.
- **Commit**: `feat(study): churn label-gate re-derivation harness + committed verdict`

### Phase 3 — frontend readout card

- **Goal**: operators see the study's verdict and its honest limits.
- **Files**: `lib/api/churn-label-gate.ts`, `components/settings/ChurnLabelGateCard.tsx`,

- **Validation**: `pnpm test` + `pnpm lint` in `services/frontend-web`; a component test

- **Commit**: `feat(ui): churn label-gate verdict card on Settings → AI`

## 4. Testing strategy

- Route tests: present / absent / org-scoped / RBAC-free read (mirror sentiment accuracy).
- Script determinism test (if the core is importable in backend tests): rerun in-process
  with a small seed → identical crossover within tolerance.
- Frontend: card component test, 4 states; page test asserts the card mounts.

## 5. Environment & secrets

- sklearn is in backend-api requirements (churn calibrator already imports it). No new env.

## 6. Edge cases & error handling

- Absent artifact → explicit empty state, never 500 (route never raises).
- Malformed artifact JSON → empty state + logged warning.
- Verdict "no defensible gate" → per PRD abort/continue: aspects 3-6 proceed, spine dormant;
  the card states it plainly.

## 7. Agent execution notes

- Checkpoint before committing the artifact: the user should see the actual numbers and
  the verdict line before they're committed. This is the one gate-review moment in the aspect.
- The harness must NOT import `analyzer.churn_classifier` (doesn't exist yet).
- `backtest_churn.py` uses `--db-url` — do NOT reuse that; the study is simulation-only
  and must run with zero DB access.
