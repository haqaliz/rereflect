## 2. Implementation phases (strict TDD)

### Phase 1 — RED: migration + columns

- **Goal**: schema changes pinned before any code reads them.
- **Files**: migration, `org_ai_config.py` (both), `test_model_parity_classifier.py`,
  migration tests
- **Steps**:
  1. Test (backend): `OrgAIConfig.churn_classifier_mode` (String(20), server_default
     `'off'`) + `churn_autopromote_hold` (Boolean, default false) exist; worker column
     parity test extended with the two new columns (RED until both models + mirror land).
  2. Create the Alembic migration chained off the single head; `alembic heads` prints
     exactly one; downgrade drops both columns; mirror columns in
     `worker-service/src/models/__init__.py`.
- **Validation**: `alembic upgrade head` + `alembic downgrade -1` round-trip in the backend
  test DB; column-parity test green.
- **Commit**: `feat(db): OrgAIConfig churn_classifier_mode + churn_autopromote_hold (TDD)`

### Phase 2 — RED: resolver mapping

- **Goal**: the resolver knows the churn mode column.
- **Files**: `classifier_resolver.py` (both copies), `test_classifier_resolver.py`,
  `test_classifier_predict_mirror.py`
- **Steps**: test `MODE_COLUMN_BY_CLASSIFIER_TYPE["churn"] == "churn_classifier_mode"` and
  `resolve_classifier(org_id, "churn", db)` returns off/shadow/auto per the column and
  None for `off`/missing (never raises) → add the mapping to BOTH copies; golden-mirror
  test stays green (the pair remains byte-identical apart from the docstring/import line).
- **Validation**: resolver + mirror tests green in both suites.
- **Commit**: `feat(resolver): churn mode mapping, mirrored byte-identical (TDD)`

### Phase 3 — GREEN: probability_updater seam

- **Goal**: auto-mode ML probability upgrades `churn_probability`; shadow logs only;
  off/no-model is byte-identical.
- **Files**: `probability_updater.py`, `test_probability_updater_churn_seam.py`
- **Steps**:
  1. Characterization test FIRST: with `churn_classifier_mode='off'` (or column absent)
     and no active churn model, `update()` output is byte-identical to current behavior
     (snapshot the current call path).
  2. Shadow: resolve `churn` → `shadow` + active churn model exists → compute ML
     probability (lazy-import core predict, active artifact from `org_classifier_models`
     `classifier_type='churn'` via the shared loader), log `rereflect.classifier.shadow`
     with the ML value + incumbent value, write nothing.
  3. Auto + active model: ML probability **replaces** the calibrated value written to
     `customer_health_scores.churn_probability` (+ derive `time_to_churn_bucket` from the
     ML value using the existing bucket logic; keep `churn_probability_low/high` from the
     bootstrap path or set from the model's CI — decide in-code and pin by test;
     `probability_computed_at` stays fresh).
  4. Auto + no active model → existing calibrated path (fallback preserved).
  5. Hysteresis guard (`_HYSTERESIS_THRESHOLD`, line 30) unchanged — pin that the ML
     value also passes through it (test).
  6. Cross-org: loader is org-scoped by (org_id, 'churn'); a foreign org's active model
     is never loaded.
- **Validation**: characterization + shadow + auto + fallback + hysteresis tests green in
  worker suite; backend suite green (no backend seam exists — probability is computed in
  the worker only; note this in the spec review).
- **Commit**: `feat(worker): churn ML probability seam — shadow logs, auto overrides (TDD)`

## 6. Edge cases & error handling

- Column absent (pre-migration DB) → resolver returns None (off) — never raises.
- Corrupt/malformed churn artifact → deserialize fails → fall back to calibrated path,
  logged (mirror `classifier_predict.py::_deserialize` defense).
- No labels → no active model → calibrated/identity path (byte-identical).
