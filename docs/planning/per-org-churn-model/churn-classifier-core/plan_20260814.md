- **New files** (package `services/analysis-engine/src/analyzer/churn_classifier/`):

## 2. Implementation phases (strict TDD — RED before GREEN, one file at a time)

### Phase 1 — labels + metrics

- **Files**: `labels.py`, `metrics.py`, `test_labels.py`, `test_metrics.py`
- **Steps**: `MIN_LABELS = 20` (parity with `churn_calibrator.py:20` — pin with a
  parity test), `LABEL_WINDOW_DAYS = 180` (parity with `calibration_refit.py:40`),
  `MARGIN = 0.02`, `RANDOM_STATE = 0`. `compute_binary_metrics(predicted_probs, labels)`
  → precision/recall/F1/auc with degenerate-case zeros (mirror `metrics.py` of
  corrections_classifier + hand-computed golden tests).
- **Validation**: `pytest tests/churn_classifier/ -q` in analysis-engine.
- **Commit**: `feat(analysis): churn classifier labels + binary metrics (TDD)`

### Phase 2 — features

- **Files**: `features.py`, `test_features.py`
- **Steps**: `build_feature_vector(row: dict) -> list[float]` + `FEATURE_NAMES` (fixed,
  documented order) over a row assembled from: 6 health components + health_score +
  risk_level (int/categorical encoded), usage fields (active_days_7d/14d/30d,
  login_count_30d, usage_score, usage_trend_state one-hot, usage_trend_pct),
  feedback aggregates (count_30d, avg_sentiment, sentiment_trend, urgent_share,
  avg_churn_risk), segment one-hot, renewal_proximity_days (or -1 when absent).
  Missing fields → documented defaults (`missing_snapshot_defaults` dict) — never raise.
- **Validation**: fixed-order determinism; all-missing row → defaults without raising;
  two identical rows → identical vectors.
- **Commit**: `feat(analysis): churn feature vector builder (TDD)`

### Phase 3 — trainer (JSON-only, lazy sklearn)

- **Files**: `trainer.py`, `test_trainer.py`
- **Steps**: `train_churn_classifier(dataset, *, random_state) -> dict artifact`
  `{model_type: "churn_logreg", version: 1, features: [...], coef: [...], intercept: float,
  classes: [0,1]}` — sklearn `LogisticRegression(max_iter=1000)` fit inside the function
  (lazy import), coefficients extracted, **no pickle, no sklearn objects persisted**.
  Deterministic under fixed seed. Serialize/deserialize helpers.
- **Validation**: artifact round-trips via `json`; `test_no_pickle`-style guard; sklearn
  import is inside the function (`test_lazy_import.py` pattern).
- **Commit**: `feat(analysis): churn logreg trainer, JSON-only artifact (TDD)`

### Phase 4 — predict (pure stdlib)

- **Files**: `predict.py`, `test_predict.py`
- **Steps**: `predict(artifact, feature_vector) -> float` — sigmoid of linear score, pure
  stdlib. **Parity test**: predictions match sklearn's `predict_proba` on training rows
  within 1e-9 (the corrections `test_predict_matches_sklearn_on_training_rows` pattern).
- **Validation**: parity test green; monotone in each coefficient's direction.
- **Commit**: `feat(analysis): churn pure-stdlib predict + sklearn parity test (TDD)`

### Phase 5 — dataset fetch + A/B evaluate

- **Files**: `dataset.py`, `evaluate.py`, `test_dataset.py`, `test_evaluate.py`
- **Steps**:
  - `fetch_churn_rows(org_id, db, *, label_window_days=180)`: SQL over
    `CustomerChurnEvent` (`source != 'auto_suggested'` — mirror the calibrator filter)
    joined to `CustomerHealth` (+ nearest `CustomerHealthHistory`/`CustomerUsageHistory`
    snapshot values passed in by the caller row set; the fetch is read-only).
  - `rows_to_dataset(rows) -> {features, labels}` (features via `features.py`).
  - `evaluate_churn(dataset, incumbent_predict, train_fn, *, min_labels, margin, random_state)`
    → reuse/adapt `corrections_classifier/evaluate.py`'s leakage-free stratified holdout
    (or k-fold when tiny): both sides scored on the SAME holdout; `promoted` iff
    `macro_f1_delta >= margin`; `EvalResult` dataclass (promoted/retained/skipped,
    deltas, n) that never raises.
  - `build_incumbent_predict(calibration_model_loader)`: wraps the calibrated heuristic as
    a `p(features) -> float` over the `churn_risk_component` (identity below MIN_LABELS) —
    the loader is injected (worker supplies the real one in aspect 4); core defines only
    the interface.
- **Validation**: leakage tests (disjoint train/holdout), `delta == 0.02` promotes,
  skip below `min_labels`, all-missing-features rows don't crash the A/B.
- **Commit**: `feat(analysis): churn dataset + leakage-free A/B vs incumbent (TDD)`

## 4. Testing strategy

- Per-file RED/GREEN above; parity + leakage + margin-boundary + determinism tests.
- `pytest tests/ -q` in analysis-engine (whole suite green; do not break
  corrections_classifier tests — `evaluate.py` must be reused, not copied, if the
  holdout semantics match).

## 5. Environment & secrets

- sklearn/numpy available in analysis-engine's venv. Nothing new.

## 6. Edge cases & error handling

- Single-class label sets (all churned) → trainer/predict must not crash; A/B returns
  `skipped` with a note (mirror `InsufficientLabelsError` handling semantics).
- `evaluate.py` never raises; malformed artifacts deserialize to None at the call site
  (aspect 5's `_deserialize` defense).

## 7. Agent execution notes

  if the study lands after this starts, apply its final field set before commit.
- Do not modify `corrections_classifier/` — prefer reuse; fork only with a documented
  reason and keep both suites green.
