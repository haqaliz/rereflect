## Phase 3 — GREEN: implement

**Goal:** make Phase 2 pass without breaking Phase 1.

**File:** `services/backend-api/src/services/automation_engine.py`

**Steps:**

1. Add a module-level constant near the top of the class or file:
   `KNOWN_NOTIFY_CHANNELS = {"dashboard", "email", "slack"}`.
2. Update the `_execute_notify` docstring (L491-496) — it currently under-declares the
   contract as `["dashboard"] | ["email"] | ["dashboard","email"]`, which is part of how
   this bug survived. State all three channels and the error contract.
3. Introduce `channel_errors: List[str] = []` before the recipient loop.
4. **Leave the `dashboard` and `email` branches untouched inside the loop.**
5. **After** the recipient loop (Slack is org-wide, once per firing — spec S4), add:
   ```python
   if "slack" in channels:
       integrations = (
           self.db.query(Integration)
           .filter(
               Integration.organization_id == org_id,
               Integration.type == "slack",
               Integration.is_active.is_(True),
           )
           .all()
       )
       if not integrations:
           channel_errors.append("slack: no active Slack integration configured")
       for integration in integrations:
           try:
               webhook_url = (integration.config or {}).get("webhook_url")
               if not webhook_url:
                   channel_errors.append(f"slack: integration {integration.id} has no webhook_url")
                   continue
               from src.api.routes.integrations import send_slack_message
               res = send_slack_message(webhook_url=webhook_url, blocks=blocks, text=text)
               if not res.get("success"):
                   channel_errors.append(f"slack: integration {integration.id}: {res.get('error')}")
           except Exception as exc:
               logger.warning("AutomationEngine: slack notify failed for integration %s: %s", integration.id, exc)
               channel_errors.append(f"slack: integration {integration.id}: {exc}")
   ```
   `Integration` import goes at module top (`from src.models.integration import Integration`)
   — it is a model, not a route, so no circular-import risk. `send_slack_message` stays a
   **lazy** import inside the branch because it lives in a route module.
6. Add the missing `else` for loudness (spec S6):
   ```python
   for ch in channels:
       if ch not in KNOWN_NOTIFY_CHANNELS:
           logger.warning("AutomationEngine: unknown notification channel %r on rule %s", ch, rule.id)
           channel_errors.append(f"unknown channel: {ch}")
   ```
7. Change the return (L567-571) to surface the error:
   ```python
   return {
       "type": "send_notification",
       "result": {"notifications_created": created_count, "slack_sent": slack_sent},
       "error": "; ".join(channel_errors) if channel_errors else None,
   }
   ```
   Keep `error: None` exactly when nothing failed, so Phase 1 characterization holds.
8. Blocks/text: build a minimal Block Kit payload from `rule.name` + `message_template`,
   with a link to the feedback item when present. Do **not** add a new formatter module;
   inline is consistent with `_dispatch_slack_alert`.

## Edge cases

| Case | Expected |
|---|---|
| `channels: []` | No channels attempted, `error is None`. Not an error — the rule asked for nothing. |
| `recipients` resolves to zero users, `channels:["slack"]` | Slack still posts once. It is org-wide, not per-user. |
| Integration `is_active=False` | Excluded by the query; counts as "no active integration" if it was the only one. |
| `config` JSON missing `webhook_url` (OAuth-only row) | Recorded as a channel error, not a crash. OAuth send is **out of scope** for this aspect. |
| Slack sender raises despite its contract | Caught; recorded; other channels unaffected. |
