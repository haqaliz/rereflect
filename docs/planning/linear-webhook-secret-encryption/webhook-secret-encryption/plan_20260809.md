## 6. Edge Cases & Error Handling

- **Missing key, callback:** 422, no row persisted (tested).
- **Missing key, verify:** decrypt raises `ValueError` → caught → no-match 401 (same as
  corrupt).
- **Changed key on an existing install:** all stored secrets undecryptable → 401 + warning
  log naming the integration id (the diagnosable path approved at the review gate).
- **Corrupt/foreign ciphertext row:** `InvalidToken` → caught → no-match 401; migration
  downgrade skips it.
- **Rows written by a pre-fix build:** plaintext → migration encrypts them at startup
  (`main.py::run_migrations` runs before traffic); until then verify 401s. No
  plaintext-tolerant fallback (deliberate).
- **Double-decrypt risk:** the single read site is `_find_integration_by_secret`; no other
  consumer reads `webhook_secret` (grep-verified). Tests assert decrypt-once behavior via
  the round-trip contract.
- **Disconnect path:** leaves the (now encrypted) stale secret in the row — unchanged
  behavior, out of scope.
