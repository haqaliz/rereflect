## Summary of decisions (read this first)

| Decision | Choice | Rationale |
|---|---|---|
| Pydantic models location | Inline in the router (`intercom_integration.py`), not a `schemas` module | The router's existing pattern keeps all models in-file (`IntercomConnectRequest` :120-126, `IntercomStatusResponse` :138-154). |
| Action field type | `action: Optional[Literal["note_only", "note_and_close"]] = None` | House `Literal` pattern (`feedback_issue_draft.py:40`, `customers.py:662`); invalid action → Pydantic 422 automatically. |
| `extra="forbid"` | `model_config = {"extra": "forbid"}` on the request model | Spec requirement; house dict-style (`automations.py:122`, `public_api.py:324`). |
| Legacy-OAuth-connection response | **409**, not 422 | Matches the router's existing 409 precedent (`/connect` :298-306) — same "connection conflict" shape, same wording style. Applied to **both** PATCH and the test probe (AC5). |
| PATCH writes on token-paste row only | Yes — `_get_active_integration` (`:172-174`); 404 when no active row | The `IntercomIntegration` row is the only writeback-column carrier (db-config-model). OAuth `Integration` row is write-only. |
| 404 vs 409 ordering | 404 first (nothing at all), then 409 (only a legacy OAuth row exists) | A 409 on an org with zero connection would be a lie; a 404 on an org with a live OAuth connection would hide the real reason. |
| `enabled` required | Yes — missing `enabled` → 422 | Spec AC1 names it explicitly; matches the CRM writeback requests (`enabled: bool` no default). |
| `action` on disable | Persisted when provided, regardless of `enabled` | Simplest idempotent contract; the frontend card always sends both fields. Stored action is inert while disabled. |
| PATCH does no validation / no HTTP | Pure config write; no `IntercomClient`, no `send_task` | Spec AC2 ("no task dispatch; no HTTP call to Intercom"). The CRM PATCH validates a field because it needs one; Intercom has nothing to validate at toggle time (scope cannot be probed — see probe decision). |
| "Enabling sends nothing" test shape | Behavioral (no `httpx.Client` construction) + static source guard (module contains no `send_task`) | The route imports no Celery, so a mocked `send_task` has nothing to attach to; the static guard mirrors the `test_integration_rbac_sweep.py` source-inspection pattern and the automations-delivery-integrity discipline ("silently never fires" is a defect class, not a test gap). |
| Probe implementation | Backend route reuses `IntercomClient.validate()` (the connect-time `GET /me` path, `:72-103`) | Spec's own lean ("connect-time GET /me validation already exists backend-side; reuse it"). `validate()` already returns `admin_id` — no new client method needed for this aspect. |
| Probe's honest scope claim | **`ok: true` never claims write scope.** Probe = credential validity + admin resolution only. `reason: "missing_write_scope"` is returned only from **recorded evidence** (`row.last_writeback_status == "missing_write_scope"`), never from a live check | Intercom `/me` does not report scopes; the only honest live scope check would mutate (empty note) — spec's open question, pinned as "credential check with recorded-evidence scope surfacing". |
| Probe reason enum | `auth_error` \| `no_admin` \| `missing_write_scope` (recorded evidence) \| `transient_error` | AC4's three named reasons plus `transient_error` for 5xx/network — a probe must never 500 and must not mislabel an upstream outage as an auth problem. Flagged in §8. |
| Probe is zero-mutation | Never writes `last_writeback_*`; never dispatches; calls only `validate()`/`close()` on the client | Spec AC4. A probe that pollutes the status grid would defeat "honest state". |
| Probe for legacy-OAuth-only orgs | 409 (same as PATCH) | The OAuth row cannot host writeback config and the worker task will not act on it in v1 (worker-writeback-task spec's open question, v1 answer), so probing its credential is not actionable. Consistency beats cleverness. |
| Status extension | Five new fields with defaults on `IntercomStatusResponse`; filled in `_build_status_response` | Spec: existing fields unchanged; disconnected payload gains the defaults (`writeback_enabled=false`, `writeback_action="note_and_close"`). |
| Dependency | Requires `db-config-model` (columns + migration) merged first | This plan reads the model as-if columns exist; it cannot run its tests until then. |

### Phase 1: PATCH /writeback + tests

- **Goal:** `PATCH /api/v1/integrations/intercom/writeback` exists with the full 404/409/422/200 contract; enabling is provably inert (no HTTP, no dispatch). Backend suite green.
- **Prerequisites:** `db-config-model` merged (columns exist on the model).
- **Files to create/modify:**
  - Modify `services/backend-api/src/api/routes/intercom_integration.py`
  - Create `services/backend-api/tests/test_intercom_writeback_config.py`
- **Implementation steps:**
  1. In `intercom_integration.py`, extend the Pydantic section (`:117-158`):
     ```python
     from typing import Literal  # extend existing typing import (:21)

     class IntercomWritebackRequest(BaseModel):
         enabled: bool
         action: Optional[Literal["note_only", "note_and_close"]] = None
         model_config = {"extra": "forbid"}

     class IntercomWritebackResponse(BaseModel):
         writeback_enabled: bool
         writeback_action: str
         last_writeback_at: Optional[datetime] = None
         last_writeback_status: Optional[str] = None
         last_writeback_error: Optional[str] = None
     ```
     (No `writeback_field_name`/`contacts_written` — those are CRM-only concepts; the intercom column set is `enabled/action/last_writeback_at/last_writeback_status/last_writeback_error`.)
  2. Add the route after `intercom_disconnect` (`:444`):
     ```python
     @router.patch(
         "/writeback",
         response_model=IntercomWritebackResponse,
         dependencies=[Depends(require_admin_or_owner)],
     )
     def intercom_configure_writeback(
         payload: IntercomWritebackRequest,
         current_org: Organization = Depends(get_current_org),
         db: Session = Depends(get_db),
     ):
         """Per-org write-back opt-in.

         Pure config write: enabling/disabling never calls Intercom, never
         enqueues a task, and never touches already-resolved items (no
         backfill-on-enable, prd.md OQ2). Writes only the token-paste
         IntercomIntegration row — the legacy OAuth row has no writeback
         columns, so an OAuth-only org gets a 409 rather than a silent
         write-nowhere.
         """
         row = _get_active_integration(db, current_org.id)
         if not row:
             if _has_active_oauth_connection(db, current_org.id):
                 raise HTTPException(
                     status_code=status.HTTP_409_CONFLICT,
                     detail=(
                         "This organization's Intercom connection uses the "
                         "legacy OAuth path, which cannot store write-back "
                         "configuration. Connect with an access token to "
                         "enable write-back."
                     ),
                 )
             raise HTTPException(
                 status_code=status.HTTP_404_NOT_FOUND,
                 detail="No active Intercom integration found.",
             )

         if payload.action is not None:
             row.writeback_action = payload.action
         row.writeback_enabled = payload.enabled
         row.updated_at = datetime.utcnow()
         db.commit()
         db.refresh(row)

         logger.info(
             "Intercom write-back %s for org %s (action=%s)",
             "enabled" if payload.enabled else "disabled",
             current_org.id,
             row.writeback_action,
         )
         return IntercomWritebackResponse(
             writeback_enabled=row.writeback_enabled,
             writeback_action=row.writeback_action,
             last_writeback_at=row.last_writeback_at,
             last_writeback_status=row.last_writeback_status,
             last_writeback_error=row.last_writeback_error,
         )
     ```
     Notes: disabling never clears `last_writeback_*` (the status grid must keep its history, mirroring the CRM routes' "disabling never touches the field name"); `datetime.utcnow()` for `updated_at` matches the file's existing style (`:366-367`).
  3. Create the test file (see §4 for the full list) with local fixtures mirroring `test_intercom_connection.py` (`owner_user`/`owner_headers` via `test_organization` conftest fixture, `member_user`/`member_headers` for RBAC, a `_connect` helper, `TEST_FERNET_KEY`).

### Phase 3: POST /writeback/test probe + tests

- **Goal:** `POST /api/v1/integrations/intercom/writeback/test` returns `{ok, reason}`; credential probe is provably zero-mutation. Backend suite green.
- **Prerequisites:** Phase 1 (connection-resolution helpers, `IntercomClient`).

  - Modify `services/backend-api/src/api/routes/intercom_integration.py`

- **Implementation steps:**
  1. Add the response model:
     ```python
     class IntercomWritebackTestResponse(BaseModel):
         ok: bool
         reason: Optional[str] = None
     ```
  2. Add the route (after the PATCH, `:444` block):
     ```python
     @router.post(
         "/writeback/test",
         response_model=IntercomWritebackTestResponse,
         dependencies=[Depends(require_admin_or_owner)],
     )
     def intercom_writeback_test(
         current_org: Organization = Depends(get_current_org),
         db: Session = Depends(get_db),
     ):
         """Live credential probe for the write-back path (S1).

         Checks exactly two things: the stored token still validates
         (GET /me) and an admin id resolves. It does NOT claim write scope:
         Intercom's /me does not report scopes, and the only honest live
         scope check would mutate, so `missing_write_scope` is reported only
         from recorded evidence on the row (a prior real write-back that
         failed with that status). A 200 {ok: true} therefore means "credible
         credential", not "scope confirmed". Never mutates anything and never
         dispatches a task.
         """
         row = _get_active_integration(db, current_org.id)
         if not row:
             if _has_active_oauth_connection(db, current_org.id):
                 raise HTTPException(
                     status_code=status.HTTP_409_CONFLICT,
                     detail=(
                         "This organization's Intercom connection uses the "
                         "legacy OAuth path, which cannot store write-back "
                         "configuration. Connect with an access token to "
                         "enable write-back."
                     ),
                 )
             raise HTTPException(
                 status_code=status.HTTP_404_NOT_FOUND,
                 detail="No active Intercom integration found.",
             )

         if row.last_writeback_status == "missing_write_scope":
             return IntercomWritebackTestResponse(
                 ok=False, reason="missing_write_scope"
             )

         try:
             plain_token = decrypt_api_key(row.access_token)
         except (ValueError, InvalidToken) as exc:
             logger.warning(
                 "Intercom writeback probe: token decrypt failed for org %s: %s",
                 current_org.id, exc,
             )
             return IntercomWritebackTestResponse(ok=False, reason="auth_error")

         client = IntercomClient(plain_token)
         try:
             try:
                 info = client.validate()
             except IntercomAuthError:
                 return IntercomWritebackTestResponse(ok=False, reason="auth_error")
             except IntercomTransientError:
                 return IntercomWritebackTestResponse(
                     ok=False, reason="transient_error"
                 )
         finally:
             _close_client(client)

         if not info.get("admin_id"):
             return IntercomWritebackTestResponse(ok=False, reason="no_admin")
         return IntercomWritebackTestResponse(ok=True, reason=None)
     ```
     Imports to add: `InvalidToken` from `cryptography.fernet` (or catch `Exception`-narrow — mirror the slack decrypt precedent `integrations.py:693-699` which catches `(ValueError, InvalidToken)`), and `decrypt_api_key` to the existing `from src.utils.encryption import ...` line (`:39`). Also add `admin_id` to the module's `IntercomClient.validate()` return contract is already handled (`:97-103`) — no client change.
- **Validation:**
  - New tests: ok/auth_error/no_admin/missing_write_scope/transient_error/404/409/zero-mutation (see §4).

## 6. Edge Cases & Error Handling

| Case | Handling (pinned) |
|---|---|
| No connection at all (PATCH / probe) | 404, `"No active Intercom integration found."` |
| Legacy OAuth row only, no token-paste row (PATCH / probe) | 409 with an honest message; nothing written; no token-paste row created. The OAuth `Integration` row has no writeback columns — a silent write-nowhere is the exact defect this guards. |
| Both checks pass (active token-paste row) | PATCH writes the token-paste row; the OAuth branch is unreachable (connect rejects OAuth+token-paste coexistence, `:298-306`). |
| Invalid `action` / unknown field / missing `enabled` | 422 via Pydantic (`Literal`, `extra="forbid"`, required field). |
| Reconnect after PATCH | `POST /connect` updates credential fields only (`:354-368`); it must not touch the writeback columns — the plan adds no connect changes, and the existing reconnect test (`test_intercom_connection.py:244-265`) still passes unmodified (Phase 1/2 validation reruns it). |

## 8. Spec ambiguities flagged

1. **409 vs 422 for the legacy-OAuth row** (spec: "return 409 with an honest message (or 422 — decide in plan)") — pinned **409**, matching the router's existing `:298-306` conflict precedent; the wording is distinct from the 404's so the two cases can't be confused.
2. **Probe scope honesty** (spec's open question) — pinned: `ok: true` = credential valid + admin resolved, never "write scope OK". `missing_write_scope` is only returned from recorded evidence (`last_writeback_status` on the row); live scope verification is impossible without mutation and is deliberately not attempted.
3. **Probe on legacy-OAuth-only orgs** — spec pins 404 for "no connection" and names the 409/422 decision for PATCH only; the plan extends the same **409** to the probe for consistency (the OAuth credential cannot host writeback config in v1, so probing it is not actionable).
4. **Probe reason enum** — AC4 names `missing_write_scope|auth_error|no_admin`; the plan adds **`transient_error`** as a fourth honest reason (5xx/429/network), because collapsing an upstream outage into `auth_error` would mislead the operator. AC4's list reads as the required paths, not an exhaustive enum.
5. **Model location** — spec does not say where the Pydantic models live; pinned to the router file per its existing pattern (`:120-158`), not the `src/schemas/` modules.
6. **"No task dispatch" test shape** — there is no Celery reference in the router to mock against; the plan pins a behavioral assertion (no `httpx.Client`) plus a static source guard (no `send_task`/`celery` in the module), following the repo's source-inspection test precedent.
7. **`action` semantics on disable** — spec implies `action` is only meaningful when enabling; the plan persists it whenever provided (idempotent, frontend-friendly) and keeps `last_writeback_*` history on disable, mirroring the CRM routes' "disabling never touches the rest".
8. **Probe zero-mutation scope** — the plan extends "no note, no close" to "no write to the integration row at all": a probe must not advance `last_writeback_*`, or the status grid would stop reflecting real write-backs.
