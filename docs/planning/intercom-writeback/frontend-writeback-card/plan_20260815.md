**Goal:** types compile under strict mode and the two new endpoints are contract-tested (AC 5 partial).

**Steps (TDD: write `lib/api/__tests__/intercom.test.ts` first, mirroring `lib/api/__tests__/hubspot.test.ts:1-11,70-130` — `vi.mock('@/lib/api-client', …)` with get/post/delete/patch):**

1. Extend `IntercomConnectionStatus` (intercom.ts:16-33) with the five fields, mirroring `hubspot.ts:17-23`:

2. Add request/response types:
   ```ts

     enabled: boolean;
     action?: 'note_only' | 'note_and_close';
   }

     writeback_enabled: boolean;
     writeback_action: 'note_only' | 'note_and_close' | null;

     last_writeback_status: string | null;
     last_writeback_error: string | null;

     ok: boolean;
     reason: string | null;
   }
   ```
3. Add to `intercomAPI` (hubspot.ts:166-183 precedent):
   ```ts
   updateWriteback: async ({ enabled, action }: IntercomWritebackConfig): Promise<IntercomWritebackResponse> => {
     const response = await apiClient.patch('/api/v1/integrations/intercom/writeback', { enabled, action });
     return response.data;
   },
   testWriteback: async (): Promise<IntercomWritebackTestResponse> => {
     const response = await apiClient.post('/api/v1/integrations/intercom/writeback/test');
   ```

## Edge cases & error handling

- **Failed PATCH** → destructive `Alert` via the HubSpot error-extraction ladder; switch/Select stay at the server's last-known value (never-optimistic) — no refetch on failure (the card shows the error instead, HubSpot precedent).
- **PATCH 404 (disconnected mid-session / race with disconnect)** → the error line shows the backend `detail`; the card unmounts on the next status refresh (`status.connected` false) — no special handling needed.
- **`writeback_action: null`** (older backend / never configured) → Select treats null as `note_and_close` (server default per PRD R1).
- **Null `last_writeback_at` / `last_writeback_status`** → grid cells omitted (HubSpot :205-220).
- **Double-click toggle / PATCH-in-flight** → Switch and Select both `disabled={saving}`; test button `disabled={testing}`.
- **`{ok: false}` from `/writeback/test` is a 200, not an error** — must render reason copy, not throw (AC 4; asserted in the test).
- **`STATUS_COPY`/`REASON_COPY` key drift** — the worker's status strings are the contract; the card falls back to the raw string via `friendlyStatus`/`friendlyReason` passthrough, so a new worker key degrades to honest raw copy rather than blank. Add a card test that each planned key maps to copy.
