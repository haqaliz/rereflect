## Summary of decisions (read this first)

| Decision | Choice | Rationale |
|---|---|---|
| Where the methods live | Instance methods on `IntercomClient` (`services/worker-service/src/clients/intercom.py`) | They share the client's `self._client` (httpx, `_TIMEOUT_SECONDS=30.0`) and `self._access_token` plumbing; same pattern as `search_conversations` (`intercom.py:89-141`). No new class, no module-level functions. |
| 404 representation | **New `IntercomNotFoundError(IntercomError)` subclass**, raised from `_handle` before the generic `>= 400` fallback | Matches the spec's "distinct IntercomNotFoundError" option and the existing worker precedent `HubSpotNotFoundError` (`test_hubspot_write_client.py:102-113`). Cleaner than a sentinel return: callers write `except IntercomNotFoundError: noop`. |
| `_handle` change scope | Add a `404 → IntercomNotFoundError` branch to the shared `_handle` (`intercom.py:73-87`) | Today 404 falls into the `>= 400` fallback and is mislabeled `IntercomAuthError` — exactly the taxonomy defect the spec names. Side effect: `search_conversations` 404 now raises `IntercomNotFoundError` instead of `IntercomAuthError`. No existing test asserts the old behavior (`test_intercom_sync.py:151-239` tests only 200/401/503/429). This is an improvement, documented in the plan. |
| Return values | `add_note` / `close_conversation` return `None` on success (raise on failure — the new contract replaces the old `bool`); `fetch_admin_id` returns `str` | Spec names the endpoints and error contract but not success returns; raise-on-error is what makes the task's error mapping ("401/403 → missing_write_scope, 404 → noop, 429/5xx → retry") possible. |
| Delete safety | `intercom_service.py` delete is safe — verified | `grep -rn intercom_service services/` returns **10 matches, all in `test_intercom.py` lines 590-684** (the `TestIntercomService` class being removed in this same change). Zero production imports in either service. Non-`services/` mentions (`DEV-TRACKING.md:512,590`, planning docs) are the **docs-tracking-changelog aspect's** job (its spec.md:57). |
| Test file | New `services/worker-service/tests/test_intercom_client_writeback.py` (spec's first option) | Keeps `test_intercom_sync.py` untouched; mirrors the write-client precedent `test_hubspot_write_client.py`. |
| Timeout | Client default `_TIMEOUT_SECONDS = 30.0` — no per-call override | Spec: "follow the existing client defaults". The backend's 15 s is not ported. |
| Auth headers on new calls | Same header dict as `search_conversations` (`Authorization: Bearer`, `Accept`, `Content-Type`) | One request-shaping convention in the file. |

## 2. Implementation Phases

### Phase 1: Worker client write surface + tests

- **Goal:** `IntercomClient` gains `add_note`, `close_conversation`, `fetch_admin_id`, and the `IntercomNotFoundError` taxonomy; new test file proves the contract. Worker suite green; backend untouched and still green.
- **Prerequisites:** None (aspect is independent — spec "Dependencies & sequencing").
- **Files to create/modify:**
  - Modify `services/worker-service/src/clients/intercom.py`
  - Create `services/worker-service/tests/test_intercom_client_writeback.py`
- **Implementation steps:**
  1. In `src/clients/intercom.py`, add after `IntercomTransientError` (currently `:41-42`):
     ```python
     class IntercomNotFoundError(IntercomError):
         """Upstream 404 (conversation missing or already closed).

         Non-retryable and not an auth problem: the caller maps it to a noop
         (close is idempotent-by-404).
         """
     ```
  2. In `_handle` (`:73-87`), insert **before** the `if resp.status_code >= 400:` fallback (and after the `>= 500` branch):
     ```python
     if resp.status_code == 404:
         raise IntercomNotFoundError(
             f"Intercom resource not found ({resp.status_code})"
         )
     ```
     Ordering matters: 404 must not reach the `>= 400` fallback that raises `IntercomAuthError`. Update the fallback's docstring/comment to note it now only sees non-404 4xx.
  3. Add three instance methods to `IntercomClient`, each mirroring `search_conversations`' shape — build the `headers` dict, wrap the httpx call in `except httpx.HTTPError as exc: raise IntercomTransientError(str(exc)) from exc`, then `self._handle(resp)`:
     - `add_note(self, conversation_id: str, admin_id: str, body: str) -> None` — `POST {INTERCOM_API_BASE}/conversations/{conversation_id}/reply`, `json={"message_type": "note", "type": "admin", "admin_id": admin_id, "body": body}`. Returns `None` on success.
     - `close_conversation(self, conversation_id: str, admin_id: str) -> None` — `POST {INTERCOM_API_BASE}/conversations/{conversation_id}/parts`, `json={"message_type": "close", "type": "admin", "admin_id": admin_id}`. Returns `None` on success.
     - `fetch_admin_id(self) -> str` — `GET {INTERCOM_API_BASE}/me`, returns `payload["id"]`. On a 200 whose JSON has no `"id"`, raise `IntercomError("Intercom /me response missing id")` (base class — malformed payload is neither retryable nor operator-scope, and the worker task treats it as a recorded, non-retried failure).
  4. Create the test file per §4 with the exact test cases listed there.
- **Validation:**

  - `cd services/worker-service && pytest tests/test_intercom_sync.py -v` — unchanged pull-path client tests still pass (guards the `_handle` 404 re-label).
  - `cd services/worker-service && pytest tests/ -v` — full worker suite green.

## 4. Testing Strategy

### New worker test file: `services/worker-service/tests/test_intercom_client_writeback.py`

Style: `httpx.MockTransport` injected via the client's `transport` param (the `TestIntercomClientSearch` pattern, `test_intercom_sync.py:151-239`) — this **is** the "transport injection works" acceptance test, since every case drives the real request-building code. No `patch()` of the client; no real network. Module-level `from __future__ import annotations`; imports inside each test (`from src.clients.intercom import ...`) matching worker test convention.

Handler helper shape (per test):
```python
def handler(request: httpx.Request) -> httpx.Response: ...
client = IntercomClient("tok", transport=httpx.MockTransport(handler))
```

Exact test cases (spec AC2, each mapped):

1. `test_add_note_posts_to_reply_url_with_exact_body` — 200; assert `request.method == "POST"`, URL `https://api.intercom.io/conversations/conv_123/reply`, `request.headers["authorization"] == "Bearer tok"`, body == `{"message_type": "note", "type": "admin", "admin_id": "admin_1", "body": "Feedback categorized as pain point."}`; returns `None`.
2. `test_close_conversation_posts_to_parts_url_with_exact_body` — 200; assert URL `https://api.intercom.io/conversations/conv_456/parts`, body == `{"message_type": "close", "type": "admin", "admin_id": "admin_2"}`; returns `None`.
3. `test_fetch_admin_id_returns_me_id` — 200 `{"id": "admin_99", "type": "admin"}`; assert GET URL `https://api.intercom.io/me`, result `"admin_99"`.
4. `test_add_note_401_raises_auth_error` — 401 → `IntercomAuthError`.
5. `test_add_note_403_raises_auth_error` — 403 → `IntercomAuthError` (spec: 403 ported to `IntercomAuthError`).
6. `test_close_conversation_404_raises_not_found_error` — 404 → `IntercomNotFoundError`, and assert it is a subclass of `IntercomError` and **not** `IntercomAuthError` (distinguishability).
7. `test_fetch_admin_id_429_raises_transient_error` — 429 → `IntercomTransientError`.
8. `test_add_note_500_raises_transient_error` — 503 (or 500) → `IntercomTransientError`.
9. `test_add_note_network_error_raises_transient_error` — handler raises `httpx.HTTPError("Connection failed")` → `IntercomTransientError` (ports `test_add_note_returns_false_on_error`'s failure case; the new contract raises instead of returning `False`).
10. `test_fetch_admin_id_missing_id_raises_base_error` — 200 `{}` → `IntercomError` (edge case pinned in Phase 1 step 3).
11. `test_transport_injection_is_used_for_write_calls` — explicit: a handler that captures the request proves the injected `MockTransport` was hit (cheaply redundant with 1-3, but pins the AC "transport injection works" as a named test).

## 6. Edge Cases & Error Handling

| Case | Handling (pinned) |
|---|---|
| 404 on note (`/reply`) and on close (`/parts`) | Both raise `IntercomNotFoundError` — spec's open question resolved: one sentinel for "not found" and "already closed"; the task aspect maps it to `noop/already_closed` (close idempotent-by-404, prd.md R3.5). |
| 404 on `search_conversations` | Now `IntercomNotFoundError` (was mislabeled `IntercomAuthError` via the `>= 400` fallback). No test asserted the old label; `test_intercom_sync.py` cases 200/401/503/429 still pass unchanged. |
| 401 vs 403 | Both `IntercomAuthError` (existing `_handle` branch) — operator-recoverable, never auto-disable (prd.md R3.5 contract preserved). |
| 429 / 5xx / transport failure | `IntercomTransientError` — retryable; the task aspect owns retry policy (max 3, delay 30). |
| Non-404 4xx (400, 422, 405...) | `IntercomAuthError` via the existing fallback — unchanged behavior, only 404 moves. |
| 200 from `/me` without `"id"` | `IntercomError` (base) — malformed payload, not retried; recorded by the task as a failure. |
| Token never logged | `__repr__`/`__str__` already return `"<IntercomClient>"` (`:68-71`); new methods must not add logging of the token. |
| Timeout | Client-wide `_TIMEOUT_SECONDS = 30.0`; no per-method override (spec requirement). |
| `add_note`/`close_conversation` success return | `None`; the caller distinguishes success from failure purely by "no exception". Document this on the methods so the task aspect doesn't treat `None` as a payload. |

## 8. Spec ambiguities flagged

1. **404 subclass vs sentinel** — spec allows either; plan pins `IntercomNotFoundError` subclass (existing `HubSpotNotFoundError` precedent in the same test suite).
2. **Success return values** of `add_note`/`close_conversation` unspecified — pinned to `None` (raise-on-error contract).
3. **`fetch_admin_id` 200-without-`id`** unspecified — pinned to raise base `IntercomError`.
4. **Test file location** — spec offers two options; plan picks the separate `test_intercom_client_writeback.py` to keep `test_intercom_sync.py` untouched.
5. **404 semantics across endpoints** — spec's open question ("note-on-closed vs close-of-closed") resolved as one shared sentinel; also flags the latent `_handle` mislabel of 404 as auth that this change fixes.
