   ```ts
   function seedSendCustomerEmailConfig(
     config: Record<string, any>,
     templateOptions: OutreachTemplateSummary[]
   ): SendCustomerEmailConfig {
     const template = config?.template;
     const recipient = config?.recipient;
     const onlyKnownKeys = Object.keys(config ?? {}).every(k => k === 'template' || k === 'recipient');
     const valid =
       typeof template === 'string' &&
       recipient === 'customer' || recipient === 'cs_assignee' &&
       onlyKnownKeys;
     return valid
       ? { template, recipient }
       : { template: templateOptions[0]?.key ?? BUILTIN_OUTREACH_TEMPLATES[0].key, recipient: 'customer' };
   }
   ```

## 6. Edge Cases & Error Handling

- **Stale config on switch-in ([id])**: an existing action switched to `send_customer_email` must not carry `status`/`recipients`/`channels` keys — backend `extra="forbid"` would 422. Handled by `seedSendCustomerEmailConfig` (D1). The Phase 3 pin test guards this forever.
- **Registry fetch failure:** `listOutreachTemplates()` rejects → fall back to `BUILTIN_OUTREACH_TEMPLATES` and toast (PlaybookEditor precedent). The default template key must resolve to `re_engagement` in that path.
- **Unknown template key in an already-saved rule:** the select shows the raw key; the editor saves it back verbatim (the PlaybookEditor unknown-key behavior). Backend validation (action-core) decides at save time; the frontend does not hard-block.
- **Member role:** edit fields disabled and the Email Deliveries tab hidden; the deliveries fetch is skipped for members to avoid the backend 403.
- **Empty deliveries:** explicit empty state; no skeleton needed beyond the page’s existing loading pattern.
- **Deliveries endpoint shape drift:** `listDeliveries` normalizes array-or-`{deliveries: []}` envelope (the webhooks precedent returns `{deliveries: [...]}`; action-core may return either). The unit test pins the normalization.
