## Architecture decisions (locked, from PRD + interview)

1. **Hold = per-type config flag** on `OrgAIConfig`
   (`sentiment_autopromote_hold` / `category_autopromote_hold` /
   `urgency_autopromote_hold`, Boolean, default false). NOT a row-pin. The
   rolled-back version stays `is_active=True` → inherently purge-safe (90-day purge
   deletes only inactive rows), no purge change needed.
2. **Rollback engages the hold** iff it reactivates a prior/target version;
   **disable-only rollback does NOT hold** (PRD R5).
3. **Worker honors the hold as late as possible** — re-read the config row-locked
   (`with_for_update()`) after the refit lock, immediately before `_promote`; if
   held, write `OrgClassifierEvalRun(decision="held")` and skip promotion (PRD M3a).
4. **Full versioning** — `GET /classifier/versions` + `rollback?to_version_id=`.
5. **Audit** rollback + resume via `audit_service.log_action`.
6. **Untouched (G5):** promotion algorithm, `MARGIN=0.02`, `MIN_LABELS`, incumbent
   heuristic, predict-time `classifier_mode`, `OrgClassifierModel` schema,
   `analysis-engine`.
7. **No plan-tier gating** (OSS unlocked).

## Phase 2 — Worker hold guard (aspect: worker-hold-guard) — depends on Phase 1

- **Goal:** held (org, type) trains + logs `decision="held"` but never promotes;
  race-safe re-read.
- **Files:** `services/worker-service/src/tasks/classifier_training.py`
  (`retrain_org`, ~`:340-366`).
- **Implementation:**
  1. After the refit lock + `evaluate()`, before the `if result.decision=="promoted"`
    block (~`:362`): read the org's `OrgAIConfig` row `with_for_update()`, map
    `classifier_type`→hold column, compute `held = bool(getattr(config, col, False))`.
    (Config may be absent → treat as not-held.)
  2. If `held`: force `model_id=None`, and write the eval run with `decision="held"`
    (override `result.decision` for the persisted row — inspect `_insert_eval_run`
    @`:235` to pass an explicit decision or set `result.decision="held"` locally).
    Skip `_promote` entirely.
  3. If not held: unchanged (`_promote` on promoted, `_insert_eval_run` after).
  4. Keep the config read + promote/held-insert in the existing worker transaction so a
    concurrently-committed rollback is observed.
- **TDD (`services/worker-service/tests/`):**
  1. RED: seed org + corrections + a promotable challenger + `sentiment_autopromote_hold=True`;
    assert after `retrain_org` the active model id is UNCHANGED and an
    `OrgClassifierEvalRun(decision="held")` exists.
  2. RED: same but hold=False → promotes as today (`decision="promoted"`, new active).
  3. Parametrize the three types → each maps to its own column.
  4. GREEN: implement the guard.
- **Validation:** `cd services/worker-service && pytest tests/ -k "classifier and (hold or promot)" -v`; existing promotion tests pass unchanged.

## Edge cases & error handling

- Unknown `classifier_type` → 400 (all 3 new/updated endpoints).
- `to_version_id` cross-org / wrong-type / already-active / purged → 404.
- No `OrgAIConfig` row yet → get-or-create before setting hold; worker treats absent
  as not-held.
- Concurrent weekly job vs rollback → worker row-locked re-read before `_promote`.
- Disable-only rollback → never engages hold (else a modelless org freezes forever).
