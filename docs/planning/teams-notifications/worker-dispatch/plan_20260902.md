## 4. Testing strategy

- Unit: sender contract (raise on non-2xx, correct MessageCard JSON, timeout).
- Dispatch: health-drop and generic pipes — gating (user off → no send), org-wide once, per-integration failure isolation, counts keys.
- Full suite: `pytest tests/ -v` (needs Postgres + Redis for integration-heavy tests).
- Characterization: discord/slack dispatch tests unchanged.

## 5. Environment & secrets

- None new. Redis + Postgres running for the suite.

## 6. Edge cases

- No active Teams integration → silent skip (same as slack/discord today; no error surfaced in dispatch — the playbook/automation paths own loudness).
- `webhook_url` missing in config → skip integration, log, continue.
- Sender raises → caught per-integration, logged, other integrations still send.
- `channel_teams` column does not exist yet in the worker mirror (this aspect's per-user gate reads it) — **coordinate with `channel-preference`**: land the worker mirror column + this gate read in the same commit window, or gate on `getattr(pref, 'channel_teams', True)` if `channel-preference` lands later. Prefer: `channel-preference` migration/mirror lands first, then this aspect's reads are plain attribute access.
