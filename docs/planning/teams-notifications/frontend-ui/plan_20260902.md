## 4. Testing strategy

- Vitest per component/page (mirror the `.discord.test.tsx` files; a shared `.teams.test.tsx` clone per page is acceptable — keep the file names in the same `__tests__/settings/` dir).
- `npm run test` + `npm run lint` after each phase.

## 5. Environment & secrets

- None new. Manual verification later via the running stack: connect a test webhook (or a public webhook-test service URL that fails validation is fine for the 422 path).

## 6. Edge cases

- Teams URL with uppercase/mixed host casing → validator is `startsWith`-based; keep it case-sensitive and document in the help text (Microsoft URLs are lowercase in practice).
- `integration.integration_type` remains `'webhook'` → OAuth/Webhook badge renders webhook automatically (:333-337), no change needed.
- Teams integration with no `channel_name` → detail page must not render an empty channel row (assert in the Phase 5 test).
