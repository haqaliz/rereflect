- **Goal:** `TeamsWebhookCreateRequest` / `TeamsTestRequest` accept valid Teams webhook URLs and reject everything else at save time.
- **Files:** `services/backend-api/src/api/routes/integrations.py`
- **Steps:**
  1. RED: write tests first (new file `services/backend-api/tests/test_teams_integration.py`, mirroring the existing discord test file — find it with `grep -rl "discord/webhook" tests/`). Test: valid classic URL `https://outlook.office.com/webhook/<guid>@<guid>/IncomingWebhook/<id>/<id>` passes; valid Workflows URL `https://<tenant>.webhook.office.com/webhookb2/<guid>@<guid>/IncomingWebhook/<id>/<id>` passes; `https://example.com/x` → 422 with a message naming the accepted hosts.
  2. Add `TeamsWebhookCreateRequest(BaseModel)` after `DiscordWebhookCreateRequest` (:139-192): fields `name`, `webhook_url`, `triggers` (same vocab validator), `included_fields` (same vocab validator), `digest_time`, `message_template` — copy the Discord model's validators verbatim, changing only `validate_webhook_url`:
     ```python
     TEAMS_WEBHOOK_HOSTS = ("https://outlook.office.com/webhook/", "https://webhook.office.com/webhookb2/")
     @field_validator('webhook_url')
     @classmethod
     def validate_webhook_url(cls, v):
         if not v.startswith(TEAMS_WEBHOOK_HOSTS):
             raise ValueError('Invalid Teams webhook URL. Must start with '
                              'https://outlook.office.com/webhook/ or '
                              'https://<tenant>.webhook.office.com/webhookb2/')
         return v
     ```
     (Hosts are fixed strings; `webhookb2` may carry a tenant subdomain prefix — `startswith` on the fixed suffix covers both.)
  3. Add `TeamsTestRequest(BaseModel)` mirroring `DiscordTestRequest` (:195-197).
  4. GREEN: run the new tests + the full integrations suite.

## 4. Testing strategy

- Unit: validator cases (both hosts + reject), sender contract (mocked httpx: 2xx/4xx/timeout → never raise), card shape assertion.
- Route tests: 201 create, 422 invalid URL, 404 wrong org/type, 400 missing webhook_url, bookkeeping on success/failure.
- Full suite: `pytest tests/ -v` (backend, Postgres required). Characterization guarantee: run `pytest tests/ -k "slack or discord"` before/after — must be unchanged.

## 5. Environment & secrets

- None new. Local run: Postgres up, `alembic upgrade head`, `./start.sh`.

## 6. Edge cases

- `webhook_url` missing from config → 400 on test, sender never called.
- Non-2xx from Microsoft → sender returns `{"success": False, "error": ...}`; route increments `error_count`.
- Timeout (10s) → same failure path.
- Digest time parse error → 400, same message as Discord/Slack.
- Multi-tenant: org scoping identical to Discord routes (`Integration.organization_id == current_org.id`).
